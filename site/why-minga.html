WHY MINGA When to switch, and when to stay

Agent panels fight your code for the screen. Terminal agents work where your editor cannot see them.

An editor with an agent panel makes the chat, the diff and your code share one window and one focus. So you moved your agents into terminal panes. That fixed the crowding, and now the agent changes files on disk while your editor holds its own copy of them. Minga is a workbench for directing agents: they read the text you have open, unsaved changes included, and an edit you approve is staged for your review, not written over your files.

Where the terminal loop stops working

The terminal loop is a good one. A terminal multiplexer such as tmux splits one terminal into panes that keep running after you disconnect. You put Claude Code or Codex in one pane, your tests in another, and open an editor only when you need to read something closely. You get each vendor's own agent the day it ships, and nothing sits between you and it.

Here is the case that breaks it. You have retry.ex open with a change you have not saved. In the next pane, the agent edits the same file. It read the copy on disk, so it never saw your change, and it writes its version there. Your editor now holds one version and the disk holds another. You pick one to lose, or you merge them by hand.

In Minga the same moment goes differently. The agent reads the file as it is in your editor, unsaved change included. When you approve its edit, the edit is staged: Review files lists it, and both the file on disk and your open copy keep the old text. In a session you start from the editor, staged edits land only when you publish them, with SPC a p (SPC is the space bar, which opens Minga's command menu). If you changed the same lines in the meantime, Minga keeps both versions and opens a conflict review.

The same gap, two tools that each hold part of the work, shows up in three more places:

  • Review comes after the write. A terminal agent writes an approved edit into your working tree, and you read the result afterwards with git diff. In Minga, approving and publishing are separate steps, so you read every staged edit before your files change. A review buffer you can reshape for the task is planned.
  • Undo has two histories. The agent's writes are not in your editor's undo history, so you take them back with Git or with the agent's own rewind command, where it has one. Minga's undo will be split by author: u undoes only your edits, and you remove an agent's change by rejecting it.
  • Scripting stops at the pane. A multiplexer works on panes: it can start them and send them keys, but a file or an agent's tool call is outside its reach. Your editor config, your agent's hooks and your pane layout live in three places. In Minga, key bindings, editor commands and agent hooks (commands that run before an agent's tool call and can veto it) are set in one Elixir file. Task workflows, which let you or Minga write a review surface or a task board for one job, build on that (Extending Minga).

Quiet by default

An IDE gives every panel to everyone: a file tree, a tab strip, a chat, a terminal, a problems list. You close the ones you do not need, and they come back.

Minga's resting screen is your text, a plain title bar and one status line. Nothing else appears until something needs you, and then the status line says so in words: 1 needs you.

When a task needs more, you ask for it. Minga builds that view from a short definition you can read: a review surface for one change, or a task board for one spec. Keep it and it opens for your next task. Close it and the screen is your text again.

The terminal is quiet in the same way, which is one reason you moved your agents there. It cannot build you a view of the work.

Should you switch?

Not always. Minga is a pre-release, and several tools do things it does not do. These are the points that usually decide it.

If you need Minga today Otherwise
Agent edits held for review before they reach disk Yes. Approved edits are staged. In a session you start from the editor, you publish or discard them, and a clash with your own changes opens a conflict review. This is the reason to switch.
Agents that keep working after you close the laptop Yes. Run minga --headless on a server and connect with minga attach ssh://devbox/work/app. tmux on a remote machine does this too.
Claude Code or Codex themselves No. Minga runs its own agent with your Anthropic, OpenAI, Google, OpenRouter, Groq, Mistral or DeepSeek key, or a ChatGPT sign-in. It does not run the vendors' command-line agents. Stay in the terminal, or use Zed, which runs both through the Agent Client Protocol, its open protocol for hosting outside agents in the editor.
Windows, or a desktop app on Linux No. There is a macOS app and a terminal client for macOS and Linux. VS Code, Cursor and Zed ship desktop apps for Windows, Linux and macOS.
AI suggestions as you type No. Minga completes from your language server as you type. It does not predict your next edit. Cursor, VS Code with GitHub Copilot, and Zed each predict your next edit.
A debugger or a built-in terminal Neither. You keep a terminal open beside Minga. VS Code, Cursor and Zed include both.
A large extension catalogue No. Extensions are Elixir packages installed from Hex, Git or a local path, and few exist yet. VS Code's marketplace, or the Neovim and Emacs plugin ecosystems.

Coming from Neovim

  • Transfers Modal editing: motions, operators, counts, text objects such as iw and a{, registers, macros and . repeat. Language servers, tree-sitter highlighting and a terminal client that runs over SSH.
  • Changes Your Lua config and your plugins do not come with you. Config is an Elixir file, ~/.config/minga/config.exs. Agent edits arrive staged for review, not through a plugin or a terminal split.
  • Stay if Your work runs on plugins you have tuned for years, such as fugitive, telescope or oil.nvim, or you need a debugger. Also stay if you open the editor many times a day for ten-second edits: Minga starts a virtual machine and opens more slowly.

Coming from Emacs or Doom Emacs

  • Transfers Doom's leader key: SPC opens mnemonic menus that show what each next key does. Hooks, and command advice with :before, :after, :around and :override. Config written in the language the editor core is written in.
  • Changes That language is Elixir, not Lisp. SPC h r reloads options, key bindings, hooks and advice in place, but a changed extension package takes effect only when you restart (the decision record explains why).
  • Stay if Your day runs through Org mode or Magit. Minga has no Org mode and nothing as deep as Magit. Also stay if you rely on redefining package code inside the running editor.

Coming from VS Code, Cursor or Zed

  • Transfers Your shortcuts, if you ask for them: set :editing_model, :cua puts copy, paste, undo and save on the usual desktop keys in place of Vim's modes. The mouse works for clicking, selecting and scrolling. Your language servers carry over.
  • Changes Your extensions do not come with you, and settings are an Elixir file, not JSON. An approved agent edit is staged for you to publish; it is not applied to the file first.
  • Stay if You rely on AI suggestions as you type, a debugger, an extension you cannot replace, or a desktop app on Windows or Linux. Stay on Cursor if you hand work to its cloud agents.

Coming from tmux with Claude Code or Codex

  • Transfers The keyboard-first habit, and a client that runs in your terminal. Sessions that outlive your connection: minga detach leaves the agent's turn running on the server. Hooks that veto a tool call, and MCP servers (Model Context Protocol, the common way to give an agent extra tools).
  • Changes The agent is Minga's own, not the vendor's. Its approved edits are staged, not written into your working tree, and it reads your unsaved changes.
  • Stay if You want Claude Code or Codex themselves, with each vendor feature the day it ships. Also stay if an agent's pull request is all you read and you never want a view of the work in progress: staged review then adds a step you do not need.

Try it beside what you use

Minga adds no config or state files to your repository. Staged drafts live under ~/.local/share/minga/, and the code is open source under the MIT license, so you can run it next to your current tool for a week and delete it if it does not earn its place. Minga is a pre-release: the Changelog lists what has shipped.
