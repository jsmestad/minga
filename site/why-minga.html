Thesis & Architecture

Why Minga

Engineers who stopped opening their old IDE did not stop needing a working environment. They stopped needing a static text editor built for one person typing one line at a time.

1. The two-tool split 2. How Minga compares 3. Programmable workbench 4. Why the BEAM 5. What is still early

1. The two-tool split and harness churn

Ask experienced engineers what editor they use right now and many will say they barely open one anymore: they spend their day inside Claude Code, Codex, pi, or another terminal agent harness. Watch them work for ten minutes, though, and a second window is always open.

The agent runs in one terminal pane while Neovim, Emacs, or VS Code sits in the next pane for reading diffs, jumping to definitions, tracing types across three modules, and fixing the subtle bug the model missed. Nobody blindly commits a thousand-line diff from a terminal scrollback. The editor did not disappear; it was demoted into a disconnected review tool that has no idea an agent exists.

The second pain point is quieter and more exhausting: harness churn. Every few months a new terminal harness or AI editor ships a better review loop, task view, or delegation flow. Because each tool bakes its workflow and UI into a closed host, adopting a good idea means abandoning your current setup and relearning another stack.

Minga starts from a different premise, inspired by the deepest idea Emacs ever proved: your working environment should be programmable in its own language while you use it, on a runtime built for concurrent human and agent work.

2. Neither an AI sidebar nor a disconnected harness

Most coding tools fall into two camps: legacy editors retrofitted with chat sidebars, or standalone terminal harnesses with no native editing core. Both leave structural gaps when you work with agents every day.

Dimension AI-retrofitted IDEs Terminal agent harnesses Minga
Runtime model Single UI event loop; heavy extensions and streaming contend for the main thread. Standalone CLI process isolated from your editor; file watcher syncs after the fact. Supervised BEAM processes with preemptive scheduling and per-process heaps across buffers, LSP, and agents.
How agents edit files Directly mutate shared editor state or patch files through extension host bridges. Write directly to disk; conflicts with open unsaved buffers and breaks editor undo history. Route through MingaAgent.ToolRouter into in-memory buffer forks, staged review (SPC a p / SPC a P), three-way merge, and undo integration.
Code reading & auditing Full editor navigation, often bogged down by heavy Electron chrome and extension sprawl. Diff text in terminal scrollback; you flip to Neovim or VS Code to jump to definitions or edit. Native Swift/Metal macOS GUI and Go terminal client with Vim + CUA editing, LSP, 50 tree-sitter grammars, and inline diff review.
Workflow customization Fixed sidebar UX; plugin APIs wrap a host you cannot deeply reshape without forking. Prompt files, slash commands, and hooks inside a fixed terminal loop; no native programmable UI. Config and extensions in Elixir, moving toward ADR-0004 live-authored definitions you Save, activate, and Keep across projects.

If you live in Neovim + tmux + a terminal harness

You do not have to give up modal muscle memory or terminal speed to get one unified environment. Minga ships Normal, Insert, Visual, Operator-Pending, Replace, and Search modes, text objects (iw, i", a{), registers, macros, marks, dot repeat, counts, 50 compiled tree-sitter grammars, supervised LSP clients, and a Go/Bubble Tea terminal client that shares the exact same BEAM core and config as the macOS app. CUA editing is also supported when you want standard desktop shortcuts.

If you come from Emacs or Doom Emacs

Minga shares Emacs's core philosophy: your config is the same language as the editor, commands wrap with :before, :after, :around, and :override advice, hooks attach to lifecycle events, and SPC leader menus make deep command trees discoverable via Which-Key. What changes is the runtime underneath: hooks run concurrently in isolated processes instead of freezing typing, buffer-local state is enforced by per-buffer processes rather than global symbol-table conventions, and there is no single-threaded C wall blocking agent concurrency.

3. Programmability over fixed harnesses (the v0.1.0 direction)

Minga's v0.1.0 design (#3542, #3662, and ADR-0004) draws a sharp line between what stays fixed in the engine and what you or your agent can reshape.

  • Authoritative owners stay fixed. Buffer processes own canonical text, edits, and undo. Agent sessions own conversations, admitted turns, tool execution, permissions, and lossless continuation (Session Recovery). Authored workflows steer and compose those authorities rather than inventing a second task database, a second scheduler, or fake prompt-only automation.
  • Two clear ways to evolve Minga. Customize Minga by discovering supported capabilities, authoring readable Elixir source, saving to activate, inspecting the result, and keeping useful definitions across projects. Develop Minga itself through normal source changes, tests, and pull requests when a task genuinely needs a new native or engine capability.
  • Explicit boundaries instead of magic hot-reloading. Under ADR-0003, arbitrary compiled extension packages and dependencies still activate on a fresh BEAM generation so active callbacks and loaded modules never mix versions, while SPC h r reloads options, keybindings, hooks, and advice cleanly in place. Restricted live Save-to-activate definitions, grouped Save, and Keep are being specified and verified step by step as part of v0.1.0 rather than hand-waved as unrestricted VM code patching.
No hidden sandbox claims

Elixir extensions and authored definitions run with OS-user privileges inside Minga's BEAM VM, the same trust model as Emacs Lisp and Neovim Lua. Minga uses explicit session grants and source-owned cleanup for admission and recovery, not OS-level sandboxing of untrusted code. See Extension API: Trust Model.

4. Why the BEAM, and why native code still draws the screen

Most editors treat concurrency as an afterthought because human typing is slow compared to a CPU. Agentic work changes the load profile completely: multiple model streams, background sub-agents, shell commands, LSP servers, tree-sitter reparsing, and interactive editing all happen at once.

  • Preemptive scheduling and per-process GC. The BEAM allocates a separate heap per process and preemptively schedules work across cores. A busy agent session or a large LSP response cannot lock out editor input or trigger a global stop-the-world GC pause.
  • Structural fault isolation. Each buffer, agent session, LSP client, and extension lives under an OTP supervision tree. A crashed tool worker or misbehaving extension callback is contained and reported cleanly without taking down open buffers or unsaved edits.
  • Observable live state. Because everything is an OTP process, you can inspect running state with :sys.get_state/1, trace messages with :dbg, or open :observer.start() when diagnosing a workflow instead of guessing through print statements.
  • Durable headless execution. Running minga --headless keeps agent sessions alive without a display, locally or on a remote machine, with clients attaching over WebSocket and JSON-RPC (Remote Agents).

What the BEAM does not do

Picking the right runtime also means respecting its limits. Minga does not use the BEAM for GPU rendering, terminal escape-sequence layout, or syntax parsing:

  • macOS GUI: Swift 6, CoreText, and Metal 3.1 own font shaping, native chrome, accessibility, row measurement (ADR-0001), and immediate UI feedback (ADR-0005).
  • Terminal frontend: Go and Bubble Tea render the TUI over the same Semantic UI protocol (Charm TUI).
  • Parsing and native helpers: Zig runs the tree-sitter parser port across 50 compiled grammars and manages process-group isolation for agent hooks.

5. An honest accounting of what is still early

Minga is pre-release software building toward v0.1.0. If you are deciding whether to try it now or follow along until the release cut, here is where things actually stand:

Area Current status
v0.1.0 live authoring & Keep Active release milestone (#3542, #3662). Config DSL, hooks, advice, and supervised extensions ship today; live Save-to-activate definitions and Keep are gated on release qualification.
Extension ecosystem The extension runtime, minga_sdk, model routes, and runtime tree-sitter grammar loading ship today (with early extensions such as minga-org and GitExtended), but the third-party package catalog is tiny compared to MELPA, Neovim, or VS Code.
Platforms Native macOS GUI (Swift + Metal) and terminal client (Go + Bubble Tea, macOS and Linux) ship today. A native Linux desktop GUI (GTK4) is post-v0.1.0.
Inline ghost text & DAP Not shipped yet. Agent work focuses on multi-file buffer-aware sessions, staged diffs, and programmable workflows.
