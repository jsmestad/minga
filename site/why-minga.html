THESIS Design & Tradeoffs

Why Minga

Editors fail when agent panels fight your code for screen width and focus. Terminal multiplexers escape that clutter, then strand your agents outside the editor buffer. Minga is built for engineers who want one minimal, programmable workbench shared by macOS and the terminal.

1. One text-first layout 2. Beyond multiplexers 3. How Minga compares 4. Zero lock-in & roadmap

1. One text-first layout across macOS and the terminal

VS Code, Cursor, and Zed let you hide sidebars and tabs, but they remain desktop-first IDEs built around docked panels. Minga's v0.1.0 interface (ADR-0006) makes text-first the default constraint across macOS and SSH terminals, deliberately trading permanent wide-screen file trees and tab strips for one identical keyboard layout.

2. Where the terminal multiplexer loop hits a wall

Claude Code and Codex inside tmux or Herdr win when you want day-zero vendor harnesses, flat-rate subscriptions, and full Git worktrees with native build caches. The ceiling appears when editing, review, remote daemons, and agent execution live in separate tools:

  • Disconnected edits. CLI agents write on disk, requiring worktrees, file reloads, or editor bridges to coordinate with open buffers.
  • Shared undo timelines. Ordinary editor undo mixes human and agent edits. Minga separates authorship so u / ⌘Z undoes only yours while agent changes leave cleanly through Reject.
  • Terminal-edge scripting. Multiplexers script panes around external CLIs; Minga lets you reshape review buffers, hooks, and task workflows in one Elixir runtime (see Extending Minga).

Coming from Neovim

Core Vim motions, text objects (iw, i", a{), registers, macros, LSP, and terminal reach carry over, and y, n, =, and q stay strictly Vim inside code (bare review keys live only in special buffers like *minga-review*). You trade away Neovim's 15 ms LuaJIT startup and deep plugin stack (fugitive, oil.nvim, telescope) for BEAM process isolation, Elixir programmability, and native macOS + TUI parity.

Coming from Emacs or Doom Emacs

Spacebar leader menus, magit-style buffers, hooks, command advice (:before, :after, :around, :override), and self-hosted config carry straight over with per-process BEAM isolation for CPU-heavy extensions. Config, hooks, and advice reload live while compiled packages activate on restart (ADR-0003), trading away live eval-defun patching, org-mode, magit, and TRAMP.

Coming from VS Code, Cursor, or Zed

Enable standard desktop shortcuts with set :editing_model, :cua and click any visible control, deliberately trading away permanent tabs, docked sidebars, inline Tab prediction, and VS Code's marketplace for one native macOS and SSH terminal layout.

4. Zero lock-in and what comes next

Minga never writes proprietary files into your Git repo. Staged drafts and transcripts live under ~/.local/share/minga/, and the codebase is MIT open source. What is in progress for v0.1.0 and beyond:

Area Status
Minimal UI, marks & parity (ADR-0006) Catppuccin Frappé default, generated tokens, CI color/state/contrast guardrails, and author-tagged edits (Minga.Buffer.Author) are on main. Twist/Orbit surfaces, per-author undo filtering, Subagent Peek, and visual diff CI land for v0.1.0.
Task workflows (ADR-0004) Save-to-activate Elixir workflows over fixed buffer and agent owners land in v0.1.0 (Extending Minga).
Built-in terminal buffers (ADR-0008) ADR-0008 proposes libghostty-vt in a Zig helper process (not yet implemented; scoped post-prerelease).
Staged diff review & shell overlays Current prerelease review is syntax-highlighted read-only (LSP inspects published open buffers); agent shell tools run in a temp copy skipping .git and node_modules.
Inline prediction, DAP & platforms Inline Tab prediction, DAP debugging, and a Linux desktop GUI are post-v0.1.0. Signed Apple Silicon Homebrew builds and Linux x86_64/ARM64 terminal packages are available now; older Linux and Intel Macs build from source; Windows is unsupported.
