THESIS Design & Tradeoffs

Why Minga

Most AI editors pile sidebars, chat drawers, tabs, and workspace pills around your code until the text lives in a narrow strip. Terminal multiplexers escape that chrome, then strand you outside the editor. Minga takes a third path: a quiet, keyboard-first workbench where the text is the interface and the runtime is yours to reshape.

1. Why the Spine 2. Where multiplexers hit a wall 3. How Minga compares 4. Disposable & kept workflows 5. Zero lock-in & early gaps

1. Why the Spine: quiet chrome, one model on macOS and in the terminal

When we tried adding IDE workspaces, icon rails, tab bars, and status strips on top of an agentic editor, three failures appeared immediately: people lost track of whether they were in the "Editor" or "Agent" workspace, chrome competed with code for screen width, and the macOS app and terminal client drifted into two incompatible products.

ADR-0006 (The Spine) replaces all of that with ten strict rules now migrating surface by surface toward v0.1.0:

  • The resting screen is just code, a plain title bar, and one modeline. No permanent sidebar, no icon rail, no tab strip, no workspace container, and no hint legends cluttering resting views. Panels yield before code does so your buffer keeps at least 100 columns.
  • Everything else is a buffer. Tasks (*minga-tasks*), reviews (*minga-review*), diagnostics, subagent peeks, file switchers, and built-in terminals (*terminal 1*, *minga-shell*) open in bottom drawers or splits and vanish with q or esc.
  • Two marks carry identity without hijacking your theme. The Twist marks authorship in the gutter (purple for Minga, blue for you, braided purple-and-blue when you edit inside Minga's change). The Orbit marks agent state everywhere with five unmistakable shapes paired with words, and amber is reserved exclusively for Needs you.
  • Neovim and Doom Emacs discipline, with Mac polish. Press SPC and pause for which-key with live counts; hold ⌘ on macOS to reveal shortcuts on visible controls; every key has a click, and every click teaches its key.
  • One layout across macOS and the terminal. The Go TUI is not a second-class fallback; both frontends render the same Spine layout, keys, and generated tokens, verified together in CI.

2. Where the terminal multiplexer loop hits a wall

Many senior engineers moved past IDE chat sidebars to CLI agents like Claude Code and Codex inside tmux or multiplexers like Herdr. That workflow earned its following: persistent background daemons survive sleep, status panels show which sessions need approval, and you can run vendor-native CLI harnesses side by side on flat-rate subscriptions.

The ceiling shows up when you want editing, review, and agent execution inside one programmable environment:

  • Two disconnected worlds for editing and review. CLI agents write directly to disk, so coordinating parallel edits with open editor buffers requires Git worktrees, file-watcher reloads, or per-editor bridge plugins.
  • No shared authorship or per-author undo. When an agent edits a file you are editing, standard editor undo treats both authors as one linear timeline. Under Minga's Spine design, u and ⌘Z undo only your own edits while Minga's work leaves cleanly through Reject.
  • Customization stops at the terminal edge. Multiplexers script panes, status bars, hooks, and prompt files around external CLIs, but they do not own the buffer, diff review surface, or terminal command-block grammar underneath.

What if you do not want to read every line of code?

Even when your work moves up a level to specs, contracts, architecture, verification evidence, and adversarial reviews, scrolling terminal panes gets worse, not better. Minga is built so the workbench reshapes itself to fit your task, embracing disposable, customized software: stay hands-on in the buffer with inline Twist review when writing code, or spin up a task-specific spec review buffer or check workflow when supervising agents. Discard it when the work lands, or keep it across projects.

Coming from Neovim

Core Vim motions, text objects (iw, i", a{), registers, macros, marks, dot repeat, counts, language servers, and a first-class terminal client carry over directly. Crucially, ADR-0006 never hijacks y, n, =, or q inside code buffers: in-file agent review uses leader keys (SPC g k/r), a change text object (ih/ah), and ex ranges, while bare single-letter keys live only in special buffers like *minga-review* and *minga-tasks* (the same rule fugitive and gitsigns follow). Built-in terminal buffers use ⌃\ ⌃N to enter Normal mode plus ic/ac command-block text objects (yic yanks a command's output). If you rely heavily on a specific Neovim plugin stack (oil.nvim, fugitive, telescope), Minga's extension catalog is still young.

Coming from Emacs or Doom Emacs

Emacs and Doom directly inspired Minga's Spacebar leader menus (with live counts in which-key), magit-style buffer actions, hooks, command advice (:before, :after, :around, :override), and the premise that configuration belongs in the editor's own language. Minga runs hooks, buffers, language servers, and extensions in isolated Erlang VM processes with separate garbage-collected heaps instead of a single Lisp thread. The tradeoff today: config options, hooks, and advice reload live, whereas compiled extension packages activate on restart to avoid split-version bugs (ADR-0003). Personality stays quiet and only appears at the edges: Minga is Bavarian for Munich ("Servus" on welcome, "Pfiat di" on quit, and "Passt." once when a task completes).

4. Disposable and kept workflows (v0.1.0 direction)

Minga separates what stays fixed in the engine from what you or your agent can reshape for a task:

  • Core data stays with one owner. Open buffers own text, edits, and undo. Agent sessions own conversations, tool approvals, permissions, and crash-safe persistence (Session Recovery). Custom workflows compose those real primitives rather than scraping terminal output or inventing shadow databases.
  • Two paths to evolve the workbench. Customize Minga through readable Elixir config and extensions today (and live task-shaped definitions in v0.1.0), or extend Minga's native clients and core engine through ordinary pull requests when you need a new low-level capability.
  • Explicit boundaries for safety and recovery. Extensions and authored workflows run with OS-user privileges, so human approval gates and isolated process cleanup remain explicit rather than hidden behind magic hot-patching. See Security, privacy, and reload boundaries.

5. Zero lock-in and what is still early

Trying Minga carries zero repository lock-in. Minga never writes proprietary project files or metadata into your Git repo; your code stays an ordinary directory you can open in Neovim, Zed, or VS Code at any moment. Staged agent drafts and saved transcripts live in documented local paths under ~/.local/share/minga/, and the entire codebase is MIT open source.
