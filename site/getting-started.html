Install Minga and publish your first reviewed edit

Install Minga, open a project, connect a model, then publish one small change that an agent wrote and you reviewed.

You need an Apple Silicon Mac with Homebrew, or Arch, Omarchy, Ubuntu 24.04+, Debian 13+ or Fedora. You also need an API key from a model provider and a project folder to try it on.

1. Install

Pick your platform and run the commands. Older Linux and Intel Macs build from source.

Apple Silicon macOS · Homebrew
# Desktop app (Minga.app)
brew install --cask jsmestad/minga/minga-mac
open -a Minga

# Terminal client (or install both)
brew install jsmestad/minga/minga
minga path/to/project
Arch Linux & Omarchy · pacman
# Trust signing key, register [minga] repo, and install on Arch / Omarchy
curl -fsSL https://packages.mingacode.dev/minga.asc | sudo pacman-key --add -
sudo pacman-key --lsign-key 2C5D2396B82C1278D4596A0965711C0C3853857B
curl -fsSL https://packages.mingacode.dev/arch/minga.conf | sudo tee -a /etc/pacman.conf > /dev/null
sudo pacman -Syu minga
Ubuntu 24.04+ & Debian 13+ · apt
sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://packages.mingacode.dev/minga.asc | sudo tee /etc/apt/keyrings/minga.asc > /dev/null
curl -fsSL https://packages.mingacode.dev/apt/minga.sources | sudo tee /etc/apt/sources.list.d/minga.sources > /dev/null
sudo apt update && sudo apt install minga
Fedora · dnf
sudo curl -fsSLo /etc/yum.repos.d/minga.repo https://packages.mingacode.dev/rpm/minga.repo
sudo dnf install minga
From source · older Linux & Intel macOS
git clone https://github.com/jsmestad/minga.git
cd minga
mise install          # or: asdf install
mix deps.get
mix compile && make native.support
bin/minga             # builds and starts terminal client
What you should see
  • macOS app: open -a Minga opens a window with Minga's start screen, a short list of actions (open file, file tree, command palette) with the key for each.
  • Terminal client: minga --version prints minga and a version number, such as minga 0.1.0-dev.412.

Each package includes its own runtime and updates through your package manager. Linux packages are signed with the key 2C5D 2396 B82C 1278 D459 6A09 6571 1C0C 3853 857B. On Fedora, dnf asks you to confirm that key on first install: check that it shows this fingerprint before you accept.

Direct downloads, upgrades and building from source

Without adding a repository. Download a standalone .deb or .rpm from GitHub Releases and install it with sudo apt install ./minga_*.deb or sudo dnf install ./minga-*.rpm. Linux packages need x86_64 or ARM64 and glibc 2.39 or newer.

Upgrades. Upgrade Homebrew installs with brew upgrade minga or brew upgrade --cask minga-mac. Linux repository installs update with your normal system upgrades.

From source. Source builds use the toolchains pinned in .tool-versions (Erlang, Elixir, Go, Zig; prefer mise). From the checkout, bin/minga starts the terminal client and takes the same arguments as minga. bin/minga-mac builds the macOS app and also requires Xcode.

2. Open a project

Use a project you know, so you can judge the change you ask for later.

Terminal client

Start Minga in the project folder:

Terminal 
cd path/to/project
minga .

Replace path/to/project with your folder. Minga opens in the agent view for that folder: your conversation with the agent, and the composer where you write to it.

macOS app

Choose File → Open… and pick any file in the project. Minga finds the project from that file: it walks up to the nearest folder that holds a marker such as .git, and scopes file finding and search to that folder.

Two things to know about keys

Minga uses Vim keys by default, so a file is always in one of two modes. In Normal mode keys are commands. In Insert mode keys type text. Press i to enter Insert mode and esc to return to Normal mode.

In Normal mode the spacebar, written SPC, opens a menu of every command. A sequence such as SPC a a means: press space, then a, then a. If you would rather use desktop shortcuts, see the keys section below.

3. Connect a model

The agent needs a model to run on. The shortest path is an API key in an environment variable, set in the terminal that starts Minga:

Terminal 
export ANTHROPIC_API_KEY="your-key"
minga .

Replace your-key with a key from your provider's dashboard. Minga gets the variable when it starts. If Minga is already running, quit it first: press esc twice to leave the composer, then SPC q q.

The other providers work the same way: OPENAI_API_KEY, GOOGLE_API_KEY, OPENROUTER_API_KEY, GROQ_API_KEY, MISTRAL_API_KEY, DEEPSEEK_API_KEY.

If you have no key set, or you use the macOS app

An app started from Finder or the Dock does not get variables you exported in a terminal. Save the key in Minga instead, from the agent view: your conversation with the agent, and the composer where you write to it. If you started with minga ., you are already there. From a file, press SPC a a in Normal mode. Type this in the composer and press ↩:

Composer 
/auth anthropic

Type the key into the masked prompt. Do not paste a key into the conversation. Minga stores it in ~/.config/minga/credentials.json, readable only by you. A key in an environment variable takes precedence over a stored one.

Choose the model

Run /model in the composer. It lists the models your key can reach. Choose one, and the conversation uses it from then on.

To sign in with a ChatGPT subscription instead of an API key, run /login. Choosing a model covers a default model for new conversations and every provider.

4. Ask for a small change

Ask for something you can check at a glance. Nothing in this step changes a file on disk. That happens only when you publish, in step 6.

  1. 01

    Open the agent view

    If you started with minga ., you are already there. From a file, press SPC a a in Normal mode.

  2. 02

    Write the request and send it

    Type in the composer and press ↩ to send. If typing does nothing, press i to focus the composer first. For example:

    Composer 
    Add a short Troubleshooting section to the end of README.md.
  3. 03

    Approve the edit

    Before the agent changes the file, Minga shows an approval card. Use the card's buttons. To use keys, press esc twice to leave the composer, then y to approve this one call or n to deny it. a trusts the tool for the rest of the session, and t for the rest of the turn.

The agent reads what is in your editor, including changes you have not saved. An edit you approve is staged: the agent sees it, but the file on disk and the file open in your editor keep the old text.

5. Review it

When the agent finishes its turn, a notice says, for example, "1 agent-edited file is not on disk" and offers Publish and Discard. Read the change before you choose.

The agent view lists the files the agent changed. Choose Review on the file to read its changes. While the review has focus, ]c moves to the next change and [c to the previous one.

For this first edit, read the whole change and then publish or discard it as one. The key reference lists the keys that accept or reject single changes.

6. Publish it

Click Publish on the notice. With keys, press SPC a p from a file or the agent view and choose Publish in the prompt. In the composer, press esc twice first.

Publish writes the staged files to disk and merges them into any file you have open. Discard drops the staged edits and leaves disk and your open files as they were. Both wait until the agent's turn has finished.

If you changed the same lines yourself in the meantime, Minga keeps both versions and opens a conflict review instead of overwriting your work. There, x keeps your version and y takes the agent's.

That is your first published edit. Run git diff in the project and it shows up like any other change.

Keys and commands for your next session

You do not need these to finish the steps above. They cover the rest of a first week. In Normal mode, h j k l move, dd deletes a line and / searches.

  • SPC Command menu. Shows every group by its letter: f files, b buffers (your open files), s search, a agent.
  • SPC f f / SPC s p Find a file, or search the project. SPC b b switches between open files.
  • SPC f s / SPC q q Save, and quit. :w and :q work too.
  • SPC a a Open the agent view, or return from it to where you were.
  • SPC a p Publish or discard staged edits in one prompt.
  • SPC f p / SPC h r Open your config file, and reload it. The file is ~/.config/minga/config.exs.

In the composer

  • /model <name> Switch models in the middle of a conversation. Replace <name> with a model that /model lists.
  • /thinking high Set the thinking level to high for harder problems.
  • /tasks Inspect the checklist for this conversation.
  • /clear Start a fresh session.
  • /help List every slash command.
Prefer desktop shortcuts to Vim keys?

Add one line to ~/.config/minga/config.exs, then reload with SPC h r. In a review, desktop shortcuts use Alt+Down and Alt+Up to step through changes, Cmd+Enter (Ctrl+Enter in the terminal) to accept and Cmd+Backspace (Ctrl+Backspace in the terminal) to reject.

~/.config/minga/config.exs 
use Minga.Config

set :editing_model, :cua
Other ways to open a file

In a terminal, minga path/to/file opens that file, and minga on its own opens the start screen.

On macOS, Minga appears under Open With in Finder for any file, including dotfiles and scripts without an extension. To make it the default editor for a kind of file, select one in Finder, choose File → Get Info, pick Minga under Open with, and click Change All….
