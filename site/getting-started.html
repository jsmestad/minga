Getting Started

Install Minga alongside your current editor with zero repo lock-in, connect a model provider, review your first staged edit, and drop starter recipes into config.exs.

1. Install 2. Defaults & keys 3. Connect a model 4. First staged edit 5. Starter recipes

Tailored path: brew install --cask jsmestad/minga/minga-mac && open -a Minga · Vim modal defaults are active out of the box.

1. Install Minga

On Apple Silicon macOS, Homebrew installs signed, notarized rolling prereleases. The desktop app (minga-mac) and terminal client (minga) are independent; install whichever you want, or both.

Apple Silicon macOS · Homebrew
# Desktop app only
brew install --cask jsmestad/minga/minga-mac
open -a Minga

# Terminal client only (or install both)
brew install jsmestad/minga/minga
minga path/to/project
From source · Linux & Intel macOS
git clone https://github.com/jsmestad/minga.git
cd minga
mise install          # or: asdf install
mix deps.get
mix compile && make native.support
bin/minga             # builds and starts terminal client

Building from source requires the toolchains pinned in .tool-versions (Erlang, Elixir, Go, and Zig; prefer mise or prebuilt OTP packages to avoid compiling Erlang from scratch). Building the macOS desktop app from source (bin/minga-mac) additionally requires Xcode (make installs pinned xcodegen automatically). The first build takes several minutes while syntax grammars compile; incremental rebuilds after that are fast. Update Homebrew installs with brew upgrade minga or brew upgrade --cask minga-mac.

Prerelease build note

All commands and shortcuts below match today's rolling Homebrew prerelease build. The quiet v0.1.0 interface model (ADR-0006) is landing surface by surface ahead of the v0.1.0 release tag; if you prefer not to adjust keybindings mid-migration, check the upcoming key map in docs/design/keys.md or watch GitHub Releases for v0.1.0.

2. Zero-config defaults and core keys

You can try Minga side by side on any existing Git repository with no configuration file:

  • Zero repository footprint: Minga never drops hidden config folders or proprietary files into your project.
  • Language servers auto-attach: Any LSP binary already on your $PATH (such as gopls, rust-analyzer, typescript-language-server, or expert) attaches automatically by filetype and project root.
  • Existing API keys work automatically: Environment variables like ANTHROPIC_API_KEY and OPENAI_API_KEY are picked up immediately without re-entering them.
  • Catppuccin Frappé default theme: Ready out of the box with readable contrast across dark and light built-in themes.

Vim modal default (with optional desktop shortcuts)

Minga is Vim-first by default: pressing Spacebar (written SPC) in Normal mode opens an interactive command menu that narrows as you type (f for files, b for buffers, s for search, a for agent). Prefer standard desktop shortcuts (⌘C/⌘V/⌘S, arrows, no modes)? Create or edit ~/.config/minga/config.exs (or press SPC f p in Vim mode) and set :editing_model to :cua (note that CUA shortcuts for staged diff review are still being completed for v0.1.0):

~/.config/minga/config.exs 
use Minga.Config

# Optional: switch from Vim modes to standard desktop shortcuts (CUA)
set :editing_model, :cua

set :theme, :catppuccin_frappe
set :tab_width, 2

In Vim mode, these five groups cover your first session:

  • SPC Open the command menu. Shows every mnemonic group so you do not need to memorize shortcuts up front.
  • SPC f f / SPC s p Find a file or search across the project. Save with SPC f s (or :w), quit with SPC q q (or :q).
  • SPC a a Open or close the Agent view. SPC a a opens the tasks drawer and SPC a v opens the conversation.
  • SPC a p Publish staged agent edits once a turn finishes, or click Discard on the same notice to drop them. SPC a p opens one Publish edits… prompt that offers publish or discard.
  • SPC f p / SPC h r Open and reload ~/.config/minga/config.exs (creates a starter file on first open; reloads options, bindings, hooks, and command wrappers in place).

3. Connect a model provider

Minga runs its own built-in multi-provider agent loop over API keys (Anthropic, OpenAI, OpenAI Codex API, Google, OpenRouter, Groq, Mistral, and DeepSeek) plus custom internal gateways added through extensions.

  1. 01

    Use an existing env var or run /model

    If ANTHROPIC_API_KEY, OPENAI_API_KEY, or another provider key is already exported in your shell environment, Minga detects it automatically. Otherwise, open the Agent view (SPC a a) and run /model.

  2. 02

    Save a key through the masked prompt

    Pick a provider's API-key action (or run /auth anthropic) and enter your key in the masked prompt, never in the chat box. Keys are saved locally in ~/.config/minga/credentials.json with 0600 permissions, never logged, and never exported in session history.

  3. 03

    Choose a model and start working

    Run /model again to pick your model. Useful slash commands: /thinking high for extended reasoning, /tasks for the conversation checklist, /clear for a fresh session, and /help for the full list.

For switching models mid-session and credential precedence rules, see Agent Model Selection in the Reference docs.

4. Walk through your first staged edit

Approved agent edits do not touch your open buffers or working tree until you publish them. Every tool approval prompt uses the same keys: y approve once, a always for this session, t this turn, n deny.

  1. 01

    Prompt the agent on a file in your repo

    Ask the agent to make a change and approve its file edit tool call. Your open buffer and working tree stay unchanged while the edit stages in an isolated overlay.

  2. 02

    Review staged hunks or edit your buffer directly

    Click Review on any changed file in the Agent view to open the syntax-highlighted read-only diff viewer. In Vim Normal mode with the viewer focused, jump between hunks with ]c / [c, accept a hunk with y (or all with Y), or reject with x (or all with X). Need to edit directly or send more context? Switch to your open file buffer, edit with full LSP and undo intact, and press SPC a b (current unsaved buffer snapshot) or SPC a D (published file diagnostics) to attach context to an open draft.

    *minga-review* replaces this viewer: ]h / [h move between changes, y keeps, n rejects, and Y keeps all after a y/n confirm. Context moves under SPC a x: SPC a x b attaches this buffer and SPC a x d this file's diagnostics.

  3. 03

    Publish with three-way merge

    Press SPC a p (or click Publish in the turn-end notice) to merge staged edits into open buffers and disk with undo intact, or click Discard to drop them. If you edited overlapping lines yourself, Review opens conflict resolution (x for Keep mine, y for Use Agent version) instead of overwriting either change.

5. Four starter recipes that ship today

Drop any of these directly into ~/.config/minga/config.exs (reload live with SPC h r) or run remote agents over SSH:

PreToolUse veto hook (~/.config/minga/config.exs)
# Run a local script before any shell tool call; non-zero exit blocks the tool.
set :agent_hooks, [
  %{
    event: "PreToolUse",
    tool: "shell",
    command: "~/.config/minga/hooks/check-shell-command.sh",
    timeout_ms: 10_000
  }
]
Crash-isolated stdio MCP server (~/.config/minga/config.exs)
# Attach stdio MCP servers; if one crashes, built-in tools and other servers keep running.
set :agent_mcp_servers, [
  %{
    name: "github",
    command: "npx",
    args: ["-y", "@modelcontextprotocol/server-github"],
    env: %{"GITHUB_PERSONAL_ACCESS_TOKEN" => System.fetch_env!("GITHUB_TOKEN")}
  }
]
Lazy extension load_policy (~/.config/minga/config.exs)
# Install from Hex and defer child process startup until a command is invoked.
extension :minga_git_extended,
  hex: "minga_git_extended",
  version: "~> 0.1",
  load_policy: {:on_command, [:git_log]}
Remote headless devbox
# On your Linux devbox (stays alive across laptop sleep via systemd linger)
minga --headless

# From macOS or another terminal (zero source copy)
minga attach ssh://devbox/work/app
