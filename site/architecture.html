Architecture & The Spine

Minga puts concurrency, isolation, state ownership, and UI semantics in one Erlang VM (BEAM) core, while separate native OS processes handle macOS rendering, terminal rendering, and syntax parsing with zero shared memory.

1. Process & client boundaries 2. Staged agent edits 3. Frontend parity 4. Guarantees & tradeoffs 5. Key ADRs (0001-0008)

1. One concurrent core, thin native OS processes

Minga uses four languages deliberately, each behind a strict OS process boundary so nothing shares memory across them. Elixir on the Erlang VM owns everything concurrent and stateful (open files, agent sessions, language servers, extensions, key scopes, theme roles, and modeline priority). Swift, Go, and Zig stay intentionally thin: Swift draws macOS with CoreText and Metal, Go draws the terminal with Bubble Tea and Lip Gloss, and Zig parses C tree-sitter grammars.

2. How staged agent edits protect your open files

Agent file tools in Minga have no blind filesystem write fallback. Approved edits land in an isolated staging overlay while your open buffers and working tree remain untouched until you explicitly publish or discard them.

3. Keeping macOS and the terminal in lockstep

Frontend parity is enforced in code and CI (docs/design/storyboard.md):

  • Generated UI tokens & CI guards. Semantic roles (minga, you, needs_you, failure, done) generate from docs/design_tokens.toml into Swift, Go, and Elixir via mix codegen, enforced by color-literal, state-word, and WCAG contrast tests across Catppuccin Frappé (default), AstroDark, and light themes.
  • Side-by-side visual diffs. Shared scenario fixtures in docs/design/scenarios.toml render offscreen on macOS (wide/narrow) and in the Go TUI (truecolor/16-color) to flag drift on UI PRs (v0.1.0).
  • Automated keyboard checks. Headless tests verify keyboard/mouse reachability, <= 3 esc/q presses back to editing, defined empty states, and zero focus theft.
  • Progressive terminal support. Uses Kitty keyboard, OSC 52 clipboard, and mode 2026 sync down to 16-color terminals; vector gutter marks, OSC 8 links, OSC 9/777 alerts, OSC 9;4 tab progress, mode 1004 focus dimming, and :checkhealth terminal follow for v0.1.0.

4. Runtime guarantees and tradeoffs

  • Ordered input, isolated background work. Interactive input stays serialized in one editor mailbox while buffers, LSPs, hooks, MCP servers, extensions, and agents run in preemptive BEAM processes with separate heaps; fast model streams coalesce ahead of typing.
  • Staging boundaries. Today's review pane is read-only and LSPs inspect published buffers; agent shell commands materialize the overlay into a temp directory skipping .git and node_modules.
  • Crash-safe tools and retained logs. Tool calls write ahead to disk before execution (never replayed on crash), and full shell output persists beyond the 51 KiB model preview across compactions and restarts (Session Recovery).

5. Architecture Decision Records (0001-0008)

Eight structural invariants recorded in the repository:

  • ADR-0001 Clients own viewport row fit. Swift and Go measure visible rows and report that count; the core never guesses rows from pixel math.
  • ADR-0002 Explicit state owners. Each sub-state has one owning writer module while interactive commands serialize in one editor mailbox.
  • ADR-0003 Compiled extensions activate on restart. Config reloads live; compiled packages activate in a fresh VM generation to prevent split-version bugs.
  • ADR-0004 Task workflows over fixed owners (v0.1.0). Readable Elixir workflows compose real buffer, agent, and permission primitives without shadow state.
  • ADR-0005 Clients own immediate motion. Smooth trackpad scrolling and local previews stay native while edits and cursors stay authoritative in the core.
  • ADR-0006 The Spine (v0.1.0). One minimal layout across macOS and terminal, on-demand drawers, Twist/Orbit marks, per-author undo, Vim keys preserved in files, and generated token parity (docs/design/).
  • ADR-0007 CUA is a key profile. Standard desktop shortcuts live in a named allow-list profile without altering core editing commands.
  • ADR-0008 Terminal engine (Proposed). Selects libghostty-vt in a Zig helper process (libvterm fallback) with the BEAM owning terminal buffers.
