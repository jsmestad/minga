Architecture & The Spine

Minga puts concurrency, isolation, state ownership, and UI semantics in one Erlang VM (BEAM) core, while separate native OS processes handle macOS rendering, terminal rendering, and syntax parsing with zero shared memory.

1. Process & client boundaries 2. Staged agent edits 3. Frontend parity 4. Guarantees & tradeoffs 5. Key ADRs (0001-0006)

1. One concurrent core, thin native OS processes

Minga uses four languages deliberately, each behind a strict OS process boundary so nothing shares memory across them. Elixir on the Erlang VM owns everything concurrent and stateful (open files, agent sessions, language servers, extensions, key scopes, theme roles, and modeline priority). Swift, Go, and Zig stay intentionally thin: Swift draws macOS with CoreText and Metal, Go draws the terminal with Bubble Tea and Lip Gloss, and Zig parses C tree-sitter grammars.

2. How staged agent edits protect your open files

Agent file tools in Minga have no blind filesystem write fallback. Approved edits land in an isolated staging overlay while your open buffers and working tree remain untouched until you explicitly publish or discard them.

3. Keeping macOS and the terminal in lockstep

Two frontends drift apart one reasonable local shortcut at a time. Prose style guides do not stop drift because nothing fails when Swift or Go diverges. The parity architecture (docs/design/storyboard.md) is being built in two tracks toward v0.1.0:

  • Single source of truth for UI tokens (Track 1 on main, Track 2 building). Every color is a semantic theme role (minga, you, needs_you, failure, done) defined once and generated into Swift, Go, and Elixir via mix codegen, with a planned guardrail rejecting hard-coded colors outside generated files. Every scenario renders in Catppuccin Frappé (default), AstroDark, and a light theme (Catppuccin Latte or One Light).
  • Side-by-side visual diffs across clients (Track 1 scenario inventory landed; Track 2 factory next). Today, docs/design/scenarios.toml inventories every screen and flow map with local invariant checks in design/tools/storyboard/check.py. Track 2 wires those scenario IDs into offscreen macOS (wide and narrow) and Go TUI (truecolor and 16-color) renders so every UI pull request publishes visual diffs against main.
  • Automated keyboard and navigation checks (Track 2). A headless explorer starts in every scenario, fires every active key binding, and verifies invariants in CI: every screen reachable by keyboard alone and mouse alone, at most three esc or q presses back to plain editing with focus restored, no dead-end bindings, every error naming a next action, defined empty states, and zero focus-stealing interruptions.
  • Progressive terminal protocol detection. The Go TUI uses modern terminal features (Kitty keyboard protocol, OSC 52 clipboard, mode 2026 synchronized output) and degrades quietly down to 16-color terminals. Next: Kitty graphics for vector gutter marks with two-tone block fallbacks, OSC 8 clickable file:line, OSC 9/777 notifications, OSC 9;4 tab progress, mode 1004 focus dimming, and :checkhealth terminal to inspect what was detected.

4. Real runtime guarantees and real tradeoffs

  • One ordered interactive mailbox, isolated background work. Editor input stays serialized in one process so keystrokes, drawer transitions, and render frames remain strictly ordered, while open buffers, language servers, save hooks, MCP servers, extensions, and agent sessions each run in separate preemptively scheduled processes with separate heaps. Fast model streams coalesce ahead of the editor mailbox so token deltas do not queue ahead of typing.
  • Current staging tradeoffs (worth knowing). Because staged edits stay off your working tree until you publish, language servers inspect the published open buffer rather than unpublished forks, and today's diff review pane is a syntax-highlighted read-only viewer (switch to the buffer to hand-edit). When an agent runs shell commands such as tests, Minga materializes the staged overlay into a temporary directory with an isolated build path so your main build stays untouched; projects relying on untracked node_modules or .git inside shell tests should keep that boundary in mind.
  • Crash-safe tool recording and retained logs. Each agent session saves the exact provider conversation beside the visible transcript, captures full shell output beyond the 51 KiB model preview so long test logs survive compaction and restarts, and records each tool call before executing it. If a process dies mid-tool, recovery marks that call indeterminate and never silently replays a side effect (Session Recovery Reference).

5. Key architectural decisions

Minga documents six structural invariants as Architecture Decision Records in the repository:

  • ADR-0001 Clients measure their own viewport rows. Swift and Go calculate how many rows fit their pixel or terminal area once and report that count; the core never guesses rows from pixel math or line spacing.
  • ADR-0002 Explicit state owners. Each sub-state has one owning module that performs its updates, while interactive commands stay serialized in one editor mailbox.
  • ADR-0003 Extension code updates activate on restart. Config reloads apply options, bindings, hooks, and advice in place; compiled extension packages activate cleanly on restart rather than mixing old and new module code mid-session.
  • ADR-0004 Programmable workflows over fixed engine owners (v0.1.0 roadmap). Author readable workflows over existing buffer, agent, and permission boundaries; save to activate; discard when one-off or reuse across projects.
  • ADR-0005 Clients own immediate visual motion. Native clients handle smooth trackpad scrolling and local previews over committed layout data while text edits and cursor position remain authoritative in the core.
  • ADR-0006 The Spine: one keyboard-first UI model across every frontend (Proposed; Catppuccin Frappé default and design inventory landed). Text, a plain title bar, and one prioritized modeline at rest; one drawer at a time for lists; Twist and Orbit marks (six state words on five shapes) driven by theme roles; per-author undo; BEAM-styled markdown spans; Vim keys preserved in files; safe quit; parity enforced via generated tokens and Storyboard CI (docs/design/).
