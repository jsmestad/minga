The real bottleneck

Spawning agents is easy. Verifying and steering their code is where you lose the day.

Follow one ordinary moment: an agent finishes a 400-line refactor, and hunk 3 has a subtle edge-case bug.

Step

Minga One programmable workbench
01 Edits land
Agent multiplexer + separate editor The CLI writes straight to disk, risking overwrites and broken undo on open buffers, or forces a separate Git worktree with another build cache and cold LSP index.
Minga Approved edits stay staged in an isolated in-memory overlay while disk and your open buffer remain untouched. Stay in one repo with one build and one LSP.
02 You check the diff
Agent multiplexer + separate editor Terminal scrollback has no jump-to-definition and no live diagnostics. You switch to Neovim or VS Code to trace callers and find what broke.
Minga Review hunks inline (]c / [c) with full syntax highlighting, jump-to-definition, and live LSP diagnostics. Background writes never yank your cursor or open file.
03 Hunk 3 is wrong
Agent multiplexer + separate editor You either hand-edit in your second editor and untangle collisions later, or type file paths and line numbers back into chat and wait for another full turn over a four-line fix.
Minga Accept good hunks (y), reject hunk 3 (x), and edit those four lines directly in Vim or CUA with undo intact. Overlapping changes open conflict review (Keep mine / Use Agent version).
04 Sending context back
Agent multiplexer + separate editor Save the file, copy compiler errors and line ranges out of your editor, and paste them into a terminal prompt hoping the agent reads the updated file.
Minga Attach your live unsaved buffer (SPC a b) or published LSP diagnostics (SPC a D) straight to the agent draft, or publish staged changes cleanly (SPC a p).
05 Improving the loop
Agent multiplexer + separate editor Customizing a multiplexer changes tabs, status bars, and shell scripts around an opaque CLI. It cannot bind buffer edits, diagnostics, and agent turns into one workflow.
Minga Write it yourself or ask the agent to build a sharper review surface or check workflow in readable source over real buffer and agent state, save to activate, and discard or keep it across projects.

When a PTY multiplexer is the right fit

If your workflow is launching six unrelated CLI agents across separate repositories and checking in occasionally from a status sidebar or phone, tools like Herdr are built for that. Minga is built for engineers who stay close to the code.

What about AI-retrofitted IDEs?

Cursor and VS Code put chat beside your editor, but on a single-threaded host with fixed panels you cannot deeply reprogram. Minga keeps editing and agents together without giving up responsiveness or owning your workflow.

Programmability

Shape the actual engine, not shell panes wrapped around it.

Minga works with any language you write. Just as Lua configures Neovim and Elisp configures Emacs, Elixir is Minga's extension language, and you can write it yourself or let the agent author readable source for you.

  • Write it yourself or ask the agent

    Configure options, keybindings, concurrent hooks, command advice, and installable extensions today in ~/.config/minga/config.exs. Toward v0.1.0, ask Minga's agent to author workflow and interface improvements over the same fixed buffer, agent, and permission owners.

  • Save to activate, inspect the diff

    Real workflow code sits in readable source files you can inspect, test, and version in Git. There is no hidden prompt masquerading as a workflow engine and no proprietary fork required for personal tooling.

  • Disposable for one task, kept when it sticks

    Reshape Minga to fit how you work on a single migration or spec review and discard it when the work lands, or Keep useful definitions shared across tabs, restarts, and repositories without regenerating them.

Pre-release honesty boundary

Ships on main today: live config/hook/advice reload (SPC h r) and supervised path, Git, and Hex extensions. Building for v0.1.0: live Save-to-activate definitions, shared composition, and Keep across sessions (see Extending Minga).

~/.config/minga/config.exs Config 
use Minga.Config

set :theme, :catppuccin_mocha
set :line_numbers, :relative
set :tab_width, 2

bind :normal, "SPC g s", :git_status, "Git status"

# Hooks run in isolated background processes so slow tools never block typing.
on :after_save, fn _buf, path ->
  if String.ends_with?(path, ".go") do
    System.cmd("gofmt", ["-w", path])
  end
end

# Wrap any command with before, after, around, or override advice.
advise :around, :format_buffer, fn execute, state ->
  errors =
    state.buffers.active
    |> Minga.Diagnostics.for_buffer()
    |> Enum.count(fn d -> d.severity == :error end)

  if errors == 0, do: execute.(state), else: state
end

# Install supervised extensions from local paths, Git, or Hex.
extension :minga_org, git: "https://github.com/jsmestad/minga-org"

Under the hood

Built on the Erlang VM so heavy agent work never stalls your editor.

Traditional single-threaded editors were built for one person typing sequentially. Minga runs its core on the BEAM to solve four failures that show up the moment humans and autonomous agents share a workspace.

  1. 01

    UI freezes and GC stutters

    Preemptive scheduling + per-process heaps

    The VM schedules lightweight processes preemptively and collects garbage per process instead of pausing everything at once. Streaming model output, language servers, and save hooks do not starve your keystrokes.

  2. 02

    One bad plugin breaks the editor

    Supervision trees + process isolation

    Buffers, agent sessions, language servers, and extensions run in separate processes with separate memory. When an extension callback or tool call fails, its supervisor isolates and recovers it while open buffers and undo history stay untouched.

  3. 03

    Agents clobber open files

    Buffer-aware forks + staged changesets

    Every open buffer owns its own isolated process. Agent file edits stage in an in-memory fork with revision checks, inline diff review, three-way merge on publish (SPC a p) or discard (SPC a P), and real undo integration. See how it works.

  4. 04

    Closing the window kills running work

    Headless daemon + durable sessions

    minga --headless keeps the runtime alive without a window, locally or on a remote host, so clients can attach, inspect, and detach while long agent runs keep going. See Remote Agents.

What the BEAM owns

Open buffers, supervision trees, agent orchestration, extensions, and semantic UI state.

Where native code takes over

The VM never rasterizes pixels or parses syntax trees. Platform-native clients handle rendering, input, and syntax parsing across explicit process boundaries (see full diagrams).

Get started

Install Minga or build from source.

Minga ships rolling prerelease builds on macOS via Homebrew and builds cleanly from source on macOS and Linux. Press SPC in Normal mode to discover commands, or open the agent panel with SPC a a.

macOS · Homebrew 
brew install --cask jsmestad/minga/minga-mac
brew install jsmestad/minga/minga
From source · macOS & Linux 
git clone https://github.com/jsmestad/minga.git
cd minga
asdf install && mix deps.get
mix compile && make native.support
bin/minga
