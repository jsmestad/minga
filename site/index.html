The problem with current tools

Neither a bolted-on AI sidebar nor a blind terminal harness.

Most engineers working seriously with agents today split their day across two disconnected tools, or keep hopping between harnesses every quarter to borrow someone else's fixed workflow.

AI-retrofitted IDEs

Fixed panels over a single thread

Legacy IDEs assume one operator typing into one event loop. Agent chat lives in a sidebar bolted onto an extension host you cannot deeply reshape, and heavy streaming or indexing still competes with your typing.

Terminal agent harnesses

Fast to start, split from your code

Harnesses write straight to disk while you switch back to Neovim or VS Code to read diffs, jump to definitions, and fix subtle bugs. When another harness ships a better review flow, you have to jump tools again.

Minga

One programmable BEAM workbench

Buffers, LSP servers, agent sessions, and extensions share one supervised Elixir runtime behind native macOS and terminal frontends. Agent edits stage in memory for inline review, and workflows live in Elixir you own.

Programmability

Stop switching tools to adopt a workflow. Author it, inspect it, and keep it.

Minga's configuration and extensions are written in Elixir, the same language as the core runtime. Your working environment evolves through readable source instead of black-box settings or editor forks.

  • Author in ordinary Elixir

    Configure options, keybindings, concurrent hooks, command advice, and supervised extensions today in ~/.config/minga/config.exs or packages built with minga_sdk. Toward v0.1.0, ask Minga's agent to author workflow and interface improvements over the same fixed buffer, agent, and permission owners.

  • Save to activate, inspect the diff

    Real workflow code sits in plain Elixir files you can read, test, and version in Git. There is no hidden prompt masquerading as a workflow engine and no proprietary fork required for personal tooling.

  • Keep what earns reuse

    Useful definitions stay shared across tabs, restarts, and repositories without regenerating them on every session, while keeping each project's local data and settings separate.

Pre-release honesty boundary

Ships on main today: Elixir config DSL, live config/hook/advice reload (SPC h r), and supervised path, Git, and Hex extensions with isolated boot compilation (ADR-0003). Building for v0.1.0: restricted live Save-to-activate definitions, shared composition, and Keep across sessions (#3542, ADR-0004).

~/.config/minga/config.exs Elixir 
use Minga.Config

set :theme, :catppuccin_mocha
set :line_numbers, :relative
set :tab_width, 2

bind :normal, "SPC g s", :git_status, "Git status"

# Hooks run in separate BEAM processes so slow tools never block typing.
on :after_save, fn _buf, path ->
  if String.ends_with?(path, ".ex") do
    System.cmd("mix", ["format", path])
  end
end

# Wrap any command with before, after, around, or override advice.
advise :around, :format_buffer, fn execute, state ->
  errors =
    state.buffers.active
    |> Minga.Diagnostics.for_buffer()
    |> Enum.count(fn d -> d.severity == :error end)

  if errors == 0, do: execute.(state), else: state
end

# Install supervised extensions from local paths, Git, or Hex.
extension :minga_org, git: "https://github.com/jsmestad/minga-org"

Runtime architecture

Why the BEAM, and where we refuse to use it.

The Erlang VM was not picked for novelty. It directly addresses four runtime failures that show up the moment humans and autonomous agents share an editor.

Problem: UI freezes and GC stutters

Preemptive scheduling and per-process heaps

The BEAM schedules lightweight processes preemptively and collects garbage per process instead of pausing the whole world. Streaming model output, LSP diagnostics, and save hooks do not starve your keystrokes.

Problem: One bad plugin breaks the editor

OTP supervision and process isolation

Buffers, agent sessions, LSP clients, and extensions run in separate processes with separate memory. When an extension callback or tool call fails, its supervisor isolates and recovers that subtree while open buffers and undo history stay untouched.

Problem: Agents clobber files behind your back

Buffer-aware forks and staged changesets

Every buffer is a GenServer process. Agent file edits route through MingaAgent.ToolRouter into in-memory buffer forks with revision checks, inline diff review, three-way merge on publish (SPC a p) or discard (SPC a P), and buffer undo integration. See Buffer-Aware Agents.

Problem: Closing the window kills running work

Headless daemon and durable sessions

minga --headless runs the BEAM runtime without a window, locally or on a remote host, exposing a WebSocket and JSON-RPC gateway so clients can attach, inspect, and detach while long sessions keep running. See Remote Agents.

Where we do not use the BEAM

The BEAM owns editing state, concurrency, agent orchestration, and semantic UI models. It does not rasterize pixels or parse syntax trees. Swift and Metal render the native macOS app, Go and Bubble Tea render the terminal client, and Zig runs the tree-sitter parser across 50 compiled grammars plus native process-group helpers. Read Architecture for the full process and protocol map.

Native frontends

Native on macOS. First-class in the terminal.

One BEAM core drives both clients over a shared Semantic UI protocol. Switch between Vim modal editing and CUA keybindings, open Doom-style SPC command menus with Which-Key, and run models across Anthropic, OpenAI, OpenAI Codex, Google, OpenRouter, Groq, Mistral, and DeepSeek.

Get started

Install Minga or build from source.

Minga ships rolling prerelease builds on macOS via Homebrew and builds cleanly from source on macOS and Linux. Press SPC in Normal mode to discover commands, or open the agent panel with SPC a a.

macOS · Homebrew 
brew install --cask jsmestad/minga/minga-mac
brew install jsmestad/minga/minga
From source · macOS & Linux 
git clone https://github.com/jsmestad/minga.git
cd minga
asdf install && mix deps.get && mix compile && make native.support
bin/minga
