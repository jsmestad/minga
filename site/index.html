A programmable workbench where text is the interface.

Code editing, parallel agents, and Elixir workflows in one keyboard-first workbench shared by macOS and the terminal. Built on the Erlang VM so every open file, language server, extension, and agent runs isolated, while agent edits stage off your working tree with syntax-highlighted diff review until you publish.

01 Interface

Two visual marks carry the identity. Chrome speaks only when state changes.

Resting screens carry no icon rail, no permanent sidebar, no tab bar, and no separate agent workspace. Every color is a semantic theme role (minga, you, needs_you, failure, done) mapped by your chosen theme, defaulting to Catppuccin Frappé.

The Twist: who wrote this line?

A thin authorship gutter replaces a separate git sign column. The strands cross once on the first line of an agent change and pin to the top as you scroll, so the review handle stays put while Minga writes.

  • Minga unreviewed Braided minga strands (mauve in Frappé); click the crossing or press SPC a y to keep and SPC a d to reject
  • Shared edit Editing inside Minga's change turns one strand into your you role on the lines you touched
  • Your lines Thin you strand (blue in Frappé) for uncommitted edits; u undoes only yours
  • Accepted Muted single strand until your next commit; rejected changes vanish cleanly

The Orbit: what is Minga doing?

Six state words on five unmistakable shapes, rendered from one canonical state value across the modeline, tasks drawer, subagent peek, and notifications. The needs_you role (peach in Frappé) is never decorative; if you see it, Minga is waiting on you.

  • Working Orbit appears only while moving TUI: ◐
  • Needs you The only state that escalates; never steals focus TUI: ◉
  • Waiting / Stopped Hollow dot paired with its word, reason, and retry timer TUI: ○
  • Failed Diamond with exact cause and one concrete next step TUI: ◆
  • Done Ready to review inline or in *minga-review* TUI: ●

Vim keys stay Vim inside code.

Inside a file, y always yanks and n always steps search. Review changes with leader keys (SPC a y / SPC a d), change text objects (ih/ah), . repeat, and line ranges. Bare single-letter actions live only in special buffers like *minga-review*.

One drawer at a time; code keeps its width.

Tasks, reviews, diagnostics, and the file switcher open as real buffers in a bottom drawer or split and close with q or esc. Panels yield before code does so your editor keeps at least 100 columns.

Safe quit and honest crash notices.

Quitting with unsaved work prompts with explicit keys (s save all, d discard only your unsaved edits, esc cancel) while Minga's unreviewed changes stay saved for next time. If a background process restarts, a clear notice says what recovered.

02 Co-authoring

Work alongside parallel agents without surrendering your buffer, undo, or focus.

Spawning agents is easy. Steering parallel runs, keeping partial diffs, and fixing edge cases without fighting your own editor is where you save the day.

01 / Authorship & Undo

Per-author undo and shared edits

Pressing u or ⌘Z undoes only your own edits, never deleting Minga's work out from under you. Agent changes are grouped per step behind revision checks and crash-safe staging, surface cleanly through the Twist gutter and *minga-review*, fill standard quickfix via :Minga review, and prompt before accepting a hunk that still has an LSP error.

02 / Parallel Agents

Subagent trees and live peek in place

When a task fans out, *minga-tasks* renders the subagent tree with live state shapes. Press SPC a i to peek at any worker in a right split with a sibling strip (◐ ◐ ● ◐ 3 of 4), folded brief, live steps, and a direct composer to message that subagent without retargeting your main thread or discarding an unsent draft.

03 / Buffers All the Way Down

Steer mid-flight or edit your prompt queue like code

Send a message in Normal mode (↩ or ⌘↩) to steer Minga while it works, or press ⌥↩ to queue follow-ups in *minga-queue*, an ordinary editable buffer where dd and p reorder upcoming prompts. Pause after Spacebar (SPC) anytime to see live counts right inside which-key.

04 / Anti-Misfire Craft

Interrupt by need, never by focus

You are mid-sentence in Insert mode when a background task asks to run a destructive command. Your cursor never jumps. Only needs_you lights up in the modeline and background notifications, an auto-opened drawer locks single-letter approval keys for 300 ms so a keystroke in flight can never hit y, and answering in one place syncs Already answered everywhere else.

03 Programmability

Build a workflow for Tuesday's migration. Discard it Wednesday, or reuse it forever.

Minga edits any language you write with zero config required to start. Just as Lua configures Neovim and Elisp configures Emacs, Elixir is Minga's extension language, scaling cleanly from five lines in config.exs to supervised packages and task-shaped workflows.

  • Start small, reload live (SPC h r)

    Configure typed options, keybindings, custom commands, background save hooks, and command wrappers in ~/.config/minga/config.exs, or install supervised extensions from Elixir's package registry (Hex), Git, or local paths.

  • Readable source with explicit grants

    Every customization lives in plain Elixir files you diff, test, and version in Git. Tune any installed extension's load_policy (eager, deferred, or on-command) directly from your config without forking it.

  • Disposable for one task, reusable when it sticks

    Author or ask Minga to build a task-specific Elixir review surface or check workflow over real buffer and agent owners. Inspect the source diff, save to activate under an explicit revocable grant (with automatic restore if a candidate fails), run it identically on macOS and in the terminal, then discard it when the PR lands or save it to reuse across repos.

Release status

Shipping on main today: live config, hook, and command-wrapper reload, Hex/Git/path extensions, custom LLM gateways, runtime grammars, and staged overlays. Landing for v0.1.0: the quiet chrome model, Twist/Orbit marks, per-author undo, and save-to-activate reusable workflows (see Extending Minga).

04 Runtime

Built on the Erlang VM for isolated work, safe automation, and remote devboxes.

Minga runs its core on the Erlang virtual machine (BEAM) so editing, language servers, extensions, MCP servers, and persistent remote agents share one concurrent runtime without stepping on each other.

  1. 01

    Zero UI freezes behind background work

    Preemptive scheduling + per-process heaps

    Every open file, language server, save hook, and agent session runs in its own lightweight process with its own garbage-collected heap, and fast model streams coalesce ahead of editor input.

  2. 02

    Crash-isolated extensions and multi-server MCP

    Supervision trees + isolated stdio MCP

    Extensions and Model Context Protocol (MCP) servers share no memory with your open buffers. If an extension raises or a GitHub/Linear/Postgres MCP server crashes mid-turn, only its prefixed tools drop out while your files, undo history, and built-in tools keep running (MCP Reference).

  3. 03

    Crash-safe tools, retained logs, and local veto hooks

    Revision checks + artifact store + PreToolUse hooks

    File edits require full-file revision checks and persist drafts outside the editor process. Long shell outputs stay stored in full beyond the 51 KiB model preview across compactions and restarts, each tool call is recorded before execution so crashes never replay side effects, and local PreToolUse shell scripts can deterministically veto risky calls (Hooks Reference).

  4. 04

    Close your laptop; agents keep working on your devbox

    Headless daemon + remote attach + corporate gateways

    Run minga --headless under systemd or launchd, attach from macOS or the terminal with minga attach ssh://devbox/work/app without copying source code, route models through internal proxies via MingaAgent.InferenceRoute, and compile extra tree-sitter grammars on demand. See Remote Agents.

What the Erlang VM owns

Open files, supervision trees, agent orchestration, extensions, key scopes, modeline segment priority, and one canonical state value for every client.

Where native code takes over

The VM never rasterizes pixels or parses syntax trees. Separate native OS processes handle macOS rendering, terminal rendering, and syntax parsing with zero shared memory (see full diagrams).

05 Parity

macOS and the terminal draw the same picture.

The terminal client is not a simplified fallback. If a screen cannot be drawn in the terminal with the same layout, the design is wrong. Rendering stays platform-native; the interaction model stays identical.

macOS Desktop App

Swift + Metal

Neovim and Doom Emacs discipline with native Mac polish: smooth trackpad scrolling, crisp CoreText typography, ligatures, system accent selection, and native menu bar and notifications without toolbar or sidebar bloat.

  • Signed, notarized Apple Silicon prereleases via Homebrew.
  • Every visible action works by keyboard or click. Holding ⌘ reveals shortcuts on visible controls.
  • Background agent alerts surface as actionable macOS notifications without stealing focus. A needs_you Dock badge joins them.

Terminal Client

Go Terminal UI

Draws the exact same layout, marks, and keys over SSH or tmux with floating drawers, crisp box geometry, and clean degradation all the way down to 16-color terminals.

  • Uses modern terminal capabilities (Ghostty, Kitty, WezTerm, iTerm2): disambiguated shortcuts, clipboard over SSH, and flicker-free frames. Crisp vector gutter marks (with two-tone block fallbacks), clickable file:line links, native notifications, and tab progress.
  • Run :checkhealth terminal anytime to inspect detected features and active fallbacks.
  • Layout and keyboard parity with macOS are tested together in CI (see Architecture).
