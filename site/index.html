Why Minga Getting Started Architecture Extending Reference GitHub

The text is the interface. Everything else stays out of the way.

A programmable, keyboard-first workbench for code and agents. No icon rail, no permanent sidebar, no tab strip, and no separate agent workspace to get lost in. One layout shared by macOS and the terminal, where Vim keys stay Vim, undo is strictly yours, and Elixir lets the workbench reshape to fit the task.

01 The Spine

Two marks carry the identity. Chrome speaks only when state changes.

Resting screens carry no icon rail, no tab bar, no key legends, and no workspace pills. Fonts and themes belong to you; Minga's identity lives in two visual marks drawn from the same vocabulary on macOS and in the terminal.

The Twist: who wrote this line?

A 10 pt authorship column replaces a separate git gutter. Its strands cross once on the first line of a change (pinning to the top of the viewport as you scroll) so the handle stays put while Minga writes.

  • Minga unreviewed Purple braided ribbon; click the crossing or use SPC g k / SPC g r
  • Shared edit Editing inside Minga's change turns the shade strand blue on your lines
  • Your lines Thin blue strand for your uncommitted edits; u undoes only yours
  • Kept Muted single purple strand until your next commit; rejected lines vanish

The Orbit: what is Minga doing?

Five distinct shapes paired with words, rendered from one BEAM value across the modeline, tasks drawer, subagent peek, and notifications. Amber is never decorative; if something is amber, Minga is waiting for you.

  • Working Orbit appears only while moving TUI: ◐
  • Needs you The only state that escalates; never steals focus TUI: ◉
  • Waiting Always names reason and countdown (e.g. retry in 40 s) TUI: ○
  • Failed Red diamond with cause and one concrete next step TUI: ◆
  • Done Ready to review ("Passt." once at completion) TUI: ●

Vim keys stay Vim. Undo is yours.

Inside a file, y still yanks and n still steps search. Handle Minga's work with SPC g k, SPC g r, text objects (ih/ah), ., and ex ranges. Pressing u or ⌘Z undoes only your own edits; Minga's edits leave through Reject.

Lists and terminals are buffers.

Tasks (*minga-tasks*), reviews (*minga-review*), diagnostics, subagent peeks, file switchers, and built-in terminals open in drawers or splits and close with q or esc. Every approval everywhere uses the same keys: y once, a session, t turn, n deny.

Built-in terminal with command blocks.

Minga's shell commands run in a visible, read-only *minga-shell* buffer marked with the purple strand. In your own terminal buffers, ]]/[[ jump command blocks, yic copies output, and ↩ on a failed command asks Minga to fix it.

02 The review loop

Spawning agents is easy. Verifying and steering their code is where you lose the day.

Follow one ordinary moment: an agent finishes a 400-line refactor, and one hunk has a subtle edge-case bug.

Step

Minga One programmable workbench
01 Edits land
Terminal multiplexers + separate editor CLI agents write directly to your working tree (colliding with open unsaved files and editor undo), or isolate each task in a separate Git worktree you have to track and merge afterward.
Minga Approved edits stage in an isolated overlay while your working tree, open files, and undo history stay untouched until you explicitly publish or discard them (and under the Spine, per-author undo guarantees u never removes Minga's work).
02 You check the diff
Terminal multiplexers + separate editor You review changes in a terminal pane or bridge over to an IDE plugin, juggling focus between the agent session and your editor tabs while new writes arrive.
Minga Review hunk by hunk without losing focus or reading position. Only Needs you escalates in the modeline and background notifications; background writes never steal focus. Under ADR-0006, review works inline via the Twist gutter or across all files in *minga-review*.
03 One hunk is wrong
Terminal multiplexers + separate editor Accepting part of a change while hand-editing the rest means mixing manual buffer edits, git hunk tools, or waiting for another agent turn over a four-line fix.
Minga Keep good hunks, reject the bad one, and edit your open file directly with Vim or standard desktop shortcuts while Vim keys stay Vim. Overlapping edits open side-by-side conflict resolution on publish instead of overwriting either side.
04 Sending context back
Terminal multiplexers + separate editor Sharing unsaved edits, failed test output, or compiler errors with a terminal CLI requires saving to disk first, piping output, or relying on per-editor bridge plugins.
Minga Attach a snapshot of your live unsaved buffer or published file diagnostics directly to an open agent draft today, or steer a running task or subagent straight from its split buffer.
05 Shaping the loop
Terminal multiplexers + separate editor Customizing a multiplexer shapes tabs, status sidebars, hooks, and prompt files around an external CLI rather than modifying the editor and review surface itself.
Minga Customize commands, hooks, advice, and supervised extensions in Elixir today. On the v0.1.0 roadmap: write or ask Minga to build task-specific buffers and review workflows over live editor and agent state, then discard when finished or keep across projects.

When Herdr, tmux, or Zed is a better fit

If you want to run Anthropic's Claude Code and OpenAI's Codex CLI side by side on flat-rate vendor subscriptions, a multiplexer like Herdr or Zed's agent protocol is built for that. If you want a compiled Rust desktop IDE with editable multibuffer diffs and Tab prediction today, look at Zed or Cursor. Minga is for engineers who want a quiet, keyboard-first workbench they own and reshape in one language.

What about Cursor and VS Code?

VS Code and Cursor have massive extension ecosystems, polished inline Tab completion, and cloud agents. Minga trades Electron, IDE sidebar sprawl, and fixed extension-host APIs for one keyboard-first layout shared by macOS and the terminal over a concurrent VM.

03 Programmability

Shape the editor itself, not shell scripts wrapped around it.

Minga edits any language you write, with sensible defaults and zero config required to start. Just as Lua configures Neovim and Elisp configures Emacs, Elixir is Minga's extension language.

  • Start small, grow without hitting a wall

    Configure options, keybindings, custom commands, background save hooks, and command wrappers in ~/.config/minga/config.exs, or install packages from local paths, Git, or Hex.

  • Readable source you can diff and test

    Workflows and extensions live in plain source files you inspect, version in Git, and approve explicitly instead of hidden prompt glue or proprietary editor forks.

  • Disposable for one task, kept when it sticks (v0.1.0)

    Toward v0.1.0, ask Minga or write source yourself to reshape the workbench for a single migration or spec review, discard it when the work lands, or keep useful definitions shared across projects.

Current release status

Ships on main today: live config, hook, and command-wrapper reload, installable path/Git/Hex extensions, staged edit overlays, and three-way merge. Migrating toward v0.1.0: the Spine chrome model (ADR-0006), built-in terminal buffers, and live save-to-activate task workflows (see Extending Minga).

04 Runtime

Built on the Erlang VM so background work stays isolated and frontends never drift.

Minga runs its core on the Erlang virtual machine (BEAM) to solve four concrete failures that appear when editing, language servers, extensions, multiple clients, and autonomous agents run together.

  1. 01

    UI freezes and GC pauses

    Preemptive scheduling + per-process heaps

    Every open file, language server, save hook, and agent session runs in its own lightweight process with its own garbage-collected heap, and fast model streams are batched ahead of editor input.

  2. 02

    One bad extension breaks your workspace

    Supervision trees + process isolation

    Extensions and tool workers share no memory with your open buffers. When a callback raises or a worker crashes, its supervisor isolates and recovers it while open files and undo history stay untouched.

  3. 03

    Agents clobber open files

    Isolated staging overlays + three-way merge

    Agent file edits require a full-file revision check and stay staged off your working tree until you publish or discard them. Staged drafts also persist independently so they survive editor crashes (see diagram).

  4. 04

    Closing the window kills running work

    Headless mode + remote attach

    minga --headless keeps agent sessions running without a window, locally or on a remote host, so you can attach and detach while long runs continue. See Remote Agents.

What the Erlang VM owns

Open files, supervision trees, agent orchestration, extensions, key scopes, modeline segment priority, and one canonical state value for every client.

Where native code takes over

The VM never rasterizes pixels or parses syntax trees. Separate native OS processes handle macOS rendering, terminal rendering, and syntax parsing (see full diagrams).

05 Parity

macOS and the terminal draw the same picture.

The Go terminal UI is not a simplified fallback. Under ADR-0006, if a macOS screen cannot be drawn in the terminal with the same layout, the design is wrong. Rendering stays platform-native; the interaction model stays identical.

macOS Desktop App

Swift + Metal

Neovim and Doom Emacs discipline with native Mac polish: smooth trackpad scrolling, CoreText typography, ligatures, system accent selection, and native menu bar and Dock notifications, without generic toolbar capsules or sidebar clutter.

  • Signed, notarized Apple Silicon prereleases via Homebrew.
  • Hold ⌘ to reveal shortcuts on visible controls; every key has a click and every click teaches its key.
  • Background Needs you alerts use Dock badges and actionable macOS notifications without stealing focus.

Terminal Client

Go + Lip Gloss

Draws the exact same Spine screens, marks, and keys over SSH or tmux using floating Lip Gloss layers, one-cell padded surface tints, and tree connectors, degrading cleanly down to 16-color terminals.

  • Auto-detects modern terminal features at startup: Kitty keyboard protocol, Kitty graphics for the exact SVG Twist (falling back to two-tone ▚/▐ cells), OSC 8 clickable file:line, OSC 9/777 notifications, OSC 9;4 tab progress, and synchronized output.
  • Inspect what your terminal supports anytime via :checkhealth terminal (landing with the Spine TUI migration).
  • Visual parity and key-walk invariants verified side by side with macOS in CI (see Storyboard CI).

06 Install

Install on macOS or build from source.

Apple Silicon macOS builds ship via Homebrew as signed, notarized prereleases. Minga never writes proprietary files into your repo, so you can try it alongside your current editor with zero lock-in. See Getting Started for Linux and Intel Mac source builds.

macOS Desktop App · Homebrew 
brew install --cask jsmestad/minga/minga-mac
open -a Minga
macOS Terminal Client · Homebrew 
brew install jsmestad/minga/minga
minga path/to/project
