EXTENDING Three Layers

Extending Minga

Minga works with any language you write, with no config required to start. When you want to customize it, Elixir is the extension language underneath: begin with five lines in config.exs, grow into supervised packages, or reshape buffers and workflows for a single task.

1. Three layers 2. config.exs 3. Extensions, hooks & gateways 4. Task-shaped workflows (v0.1.0) 5. Security, privacy & reloads

1. One language across three layers

You never outgrow a JSON schema or jump across an RPC plugin wall when your customization gets serious. Every layer shares the same Elixir runtime and composes with Minga's buffers, drawers, and key scopes instead of adding competing panels:

  • Layer 1 · config.exs Ships today, reloads live (SPC h r). Typed options, themes, per-filetype rules, keybindings, custom commands, background save hooks, PreToolUse shell veto hooks, crash-isolated stdio MCP servers, and command wrappers (advise: run code before, after, around, or instead of any built-in command).
  • Layer 2 · Extensions Ships today. Installable packages from Elixir's package registry (Hex), Git repos, or local paths using minga_sdk: declarative commands, keymap scopes, lazy load_policy overrides, custom buffer/drawer surfaces, corporate LLM gateways, and runtime-compiled syntax grammars.
  • Layer 3 · Task workflows v0.1.0 roadmap. Write or ask Minga to author readable source over existing buffer, drawer, agent, and permission primitives; inspect the diff and save to activate; discard when a one-off task ends or reuse across projects.

2. Layer 1: Everyday customization in config.exs

~/.config/minga/config.exs is ordinary Elixir with typed option validation (bad values report a clear error rather than failing silently). Lifecycle hooks run asynchronously in separate processes so slow CLI formatters or linters never block typing, and command wrappers contain exceptions so a bug in your handler never crashes the editor.

~/.config/minga/config.exs Elixir 
use Minga.Config

set :theme, :catppuccin_frappe
set :line_numbers, :hybrid
set :scroll_margin, 6

# Per-filetype option overrides take a plain keyword list.
for_filetype :go, tab_width: 4, indent_with: :tabs

# Background save hooks run in separate processes and never stall typing.
on :after_save, fn _buf, path ->
  if String.ends_with?(path, ".go") do
    System.cmd("gofmt", ["-w", path])
  end
end

# Wrap any built-in command with :before, :after, :around, or :override advice.
advise :after, :save, fn state ->
  Minga.API.message("Saved")
  state
end

# Install supervised extensions from Hex, Git, or local paths (with optional lazy loading).
extension :minga_git_extended, hex: "minga_git_extended", version: "~> 0.1"

See the Configuration Reference for every typed option, theme token, formatter override, hook, and MCP server setting.

3. Layer 2: Supervised extensions, hooks, MCP, and gateways

When a customization needs its own supervision tree, background state, buffer surface, or distribution across machines, build a package with minga_sdk. Every command, keybinding, surface, and language entry is tagged with its owning extension so disabling it tears down everything cleanly without leaving stale state behind. Users can also override any extension's load_policy (:eager, :deferred, or {:on_command, [...]}) in config.exs without forking the package.

lib/my_extension.ex · minga_sdk Elixir 
defmodule MyExtension do
  use Minga.Extension.Editor

  option :enabled, :boolean, default: true, description: "Enable extension"

  command :run_check, "Run custom project check",
    execute: {MyExtension.Commands, :run}

  keybind :normal, "SPC m c", :run_check, "Run custom check", filetype: :go

  @impl true
  def name, do: :my_extension

  @impl true
  def description, do: "Project-specific check runner"

  @impl true
  def version, do: "0.1.0"

  @impl true
  def init(_config), do: {:ok, %{}}
end

Four integration seams that ship today

  • Custom corporate LLM gateways (MingaAgent.InferenceRoute). Connect an internal company proxy, private endpoint, or custom subscription route to /model. Your route only streams model replies; Minga keeps running tool approvals, staged overlays, retries, context compaction, and session history (Model Routes Reference).
  • Deterministic PreToolUse veto hooks (:agent_hooks). Run a local shell script before any matching tool ("shell", "*_file", or "*") with JSON call arguments on stdin and POSIX process-group timeout cleanup; any non-zero exit blocks the tool and surfaces stderr in chat (Hooks Reference).
  • Crash-isolated multi-server MCP (:agent_mcp_servers). Attach multiple stdio Model Context Protocol servers (GitHub, Linear, Postgres, browsers) to each agent session. Each server's tools are safely prefixed (mcp_<server>__<tool>) and default to destructive approval; if one server exits mid-turn, only its tools drop out while built-in tools and healthy servers keep running (MCP Reference).
  • Runtime syntax grammars (Minga.Language.register). Ship tree-sitter grammar sources and Minga compiles them on demand at runtime, caches the shared library in ~/.local/share/minga/grammars/, and wires highlight queries without rebuilding Minga (Tree-Sitter Grammars Reference).

4. Layer 3: Disposable and reusable task workflows (v0.1.0 roadmap)

The v0.1.0 milestone adds a third layer between a quick config.exs edit and a full packaged extension: reshaping your workbench for a single task without maintaining a massive personal config or forking the editor.

Concrete example of the v0.1.0 target: suppose you are revising a design spec in Markdown or auditing a risky migration and want inline review comments, explicit "Send Revision" actions, attributed suggestions you can accept or reject, and a split buffer tracking check status and token usage for that task. Instead of hunting for a plugin or waiting on an editor vendor, you write or ask Minga to author that workflow in readable Elixir over Minga's existing buffer, drawer, and agent primitives. You inspect the diff, save to activate under an explicit revocable grant (with automatic restore if a candidate fails), run it identically on macOS and in the terminal, and either discard the workflow once the PR lands or save it to reuse across future projects.

Release status & stability

Layers 1 and 2 (config.exs, hooks, advice, Hex/Git/path extensions, PreToolUse hooks, MCP servers, custom model gateways, and runtime grammars) ship on main today. Layer 3 (save-to-activate disposable and reusable workflows) and the ADR-0006 minimal UI model are in active development for v0.1.0. Before v1.0, breaking changes to config options or minga_sdk are documented in the Changelog.

5. Security, privacy, and reload boundaries

If you are evaluating Minga for daily work on proprietary company code, here are the exact boundaries:

  • Explicit approval gates and extension updates. Extensions and authored workflows run with OS-user privileges inside the Erlang VM, matching Emacs Lisp and Neovim Lua (Minga isolates callback crashes so a buggy extension does not take down the editor, which is failure containment rather than an OS sandbox). Destructive agent tools (file edits, deletes, shell commands, git writes, and MCP tools by default) require explicit approval; initial extension installs run only for sources you explicitly declare in config.exs, while extension updates (SPC h e u) prompt for confirmation with git log inspection before applying; and v0.1.0 live authoring requires an explicit revocable session grant plus human review before activation.
  • Local credentials, temp overlays, and zero remote telemetry. Minga sends zero analytics or crash telemetry; network traffic goes only to the model routes, MCP servers, and language servers you configure. API keys resolve from environment variables first or save locally in ~/.config/minga/credentials.json (0600 permissions), never logged and never exported in transcripts. On work laptops, prefer shell environment variables or an internal MingaAgent.InferenceRoute proxy over storing keys on disk. Temporary shell-run overlays copy project files while skipping .git and node_modules and clean up after execution; unpublished staged drafts persist locally under ~/.local/share/minga/staged_drafts.
  • Corporate gateway & binary transparency. Teams can route exclusively through an internal proxy using MingaAgent.InferenceRoute rather than public provider endpoints. Rolling macOS desktop builds are Apple Developer ID signed and notarized, and the entire codebase is MIT open source and buildable from source.
  • Why compiled extension updates activate on restart (ADR-0003). While SPC h r reloads options, bindings, hooks, and advice in place, compiled extension packages can own supervisors, closures, and dependencies that cannot atomically cross a version boundary mid-session. Disabling an extension takes effect immediately; updated extension code activates cleanly on restart.
