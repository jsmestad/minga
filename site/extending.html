EXTENDING Three Layers

Extending Minga

Minga works with any language you write, with no config required to start. When you want to customize it, Elixir is the extension language underneath: begin with five lines in config.exs, grow into supervised packages, or reshape buffers and workflows for a single task.

1. Three layers 2. config.exs 3. Extensions & gateways 4. Task-shaped workflows (v0.1.0) 5. Security, privacy & reloads

1. One language across three layers

You never outgrow a JSON schema or jump across an RPC plugin wall when your customization gets serious. Every layer shares the same Elixir runtime and composes with Minga's buffers, drawers, and key scopes instead of adding competing chrome:

  • Layer 1 · config.exs Ships today, reloads live (SPC h r). Options, themes, per-filetype rules, keybindings, custom commands, background lifecycle hooks, and command wrappers (advise: run code before, after, around, or instead of any built-in command).
  • Layer 2 · Extensions Ships today. Installable packages from local paths, Git repos, or Elixir's package registry (Hex) using minga_sdk: declarative commands, keymap scopes, custom buffer/drawer surfaces, corporate LLM gateways, and runtime-compiled syntax grammars.
  • Layer 3 · Task workflows v0.1.0 roadmap. Write or ask Minga to author readable source over existing buffer, agent, Spine drawer, and permission primitives; review and save to activate; discard when a one-off task ends or keep across projects.

2. Layer 1: Everyday customization in config.exs

~/.config/minga/config.exs is ordinary Elixir with typed option validation (bad values report a clear error rather than failing silently). Lifecycle hooks run asynchronously in separate processes so slow CLI formatters or linters never block typing, and command wrappers contain exceptions so a bug in your handler never crashes the editor.

~/.config/minga/config.exs Elixir 
use Minga.Config

set :theme, :astrodark
set :line_numbers, :hybrid
set :scroll_margin, 6

# Per-filetype option overrides take a plain keyword list.
for_filetype :go, tab_width: 4, indent_with: :tabs

# Background save hooks run in separate processes and never stall typing.
on :after_save, fn _buf, path ->
  if String.ends_with?(path, ".go") do
    System.cmd("gofmt", ["-w", path])
  end
end

# Wrap any built-in command with :before, :after, :around, or :override advice.
advise :after, :save, fn state ->
  Minga.API.message("Saved")
  state
end

# Install supervised extensions from local paths, Git, or Hex.
extension :minga_git_extended,
  git: "https://github.com/jsmestad/minga-git-extended"

See the Configuration Reference for every typed option, theme token, formatter override, and MCP server setting.

3. Layer 2: Supervised extensions, corporate gateways, and grammars

When a customization needs its own supervision tree, background state, buffer surface, or distribution across machines, build a package with minga_sdk. Every command, keybinding, surface, and language entry is tagged with its owning extension so disabling it tears down everything cleanly without leaving stale state behind.

lib/my_extension.ex · minga_sdk Elixir 
defmodule MyExtension do
  use Minga.Extension.Editor

  option :enabled, :boolean, default: true, description: "Enable extension"

  command :run_check, "Run custom project check",
    execute: {MyExtension.Commands, :run}

  keybind :normal, "SPC m c", :run_check, "Run custom check", filetype: :go

  @impl true
  def name, do: :my_extension

  @impl true
  def description, do: "Project-specific check runner"

  @impl true
  def version, do: "0.1.0"

  @impl true
  def init(_config), do: {:ok, %{}}
end

Two extension seams worth knowing

  • Custom corporate LLM gateways (MingaAgent.InferenceRoute). Connect an internal company proxy, private endpoint, or custom subscription route to /model. Your route only streams model replies; Minga keeps running tool approvals, staged buffer overlays, retries, context compaction, and session history (Model Routes Reference).
  • Runtime syntax grammars (Minga.Language.register). Ship tree-sitter grammar sources with an extension and Minga compiles them on demand at runtime, caches the shared library in ~/.local/share/minga/grammars/, and wires highlight queries without rebuilding Minga (Tree-Sitter Grammars Reference).

4. Layer 3: Task-shaped disposable and kept workflows (v0.1.0 roadmap)

The v0.1.0 milestone adds a third layer between a quick config.exs edit and a full packaged extension: reshaping your workbench for a single task without maintaining a massive personal config or forking the editor.

Concrete example of the v0.1.0 target: suppose you are revising a design spec in Markdown and want inline review comments, explicit "Send Revision" actions, attributed suggestions you can keep or reject, and a split buffer tracking token usage and latency for that document. Instead of hunting for a plugin or waiting on an editor vendor, you ask Minga to author that workflow in readable source over Minga's existing buffer, drawer, and agent primitives. You inspect the diff, approve activation, collaborate on the spec, and either discard the workflow once the doc is done or keep it as a reusable definition across future projects.

Release status & stability

Layers 1 and 2 (config.exs, hooks, advice, installable extensions, custom model gateways, and runtime grammars) ship on main today. Layer 3 (live save-to-activate task definitions and reusable kept workflows) and the ADR-0006 Spine chrome migration are in active development for v0.1.0. Before v1.0, breaking changes to config options or minga_sdk are documented in the Changelog.

5. Security, privacy, and reload boundaries

If you are evaluating Minga for daily work on proprietary company code, here are the exact boundaries:

  • Explicit human approval gates (no silent execution). Extensions and authored workflows run with OS-user privileges inside the Erlang VM, matching Emacs Lisp and Neovim Lua (Minga isolates callback crashes so a buggy extension does not take down the editor, which is failure containment rather than an OS sandbox). Destructive agent tools (file edits, deletes, shell commands, git writes) go through Minga's explicit tool-approval policy (y once, a session, t turn, n deny), first-time Git/Hex extension installs prompt for confirmation, and v0.1.0 live authoring requires an explicit revocable session grant plus human review before activation.
  • Local credentials, zero remote telemetry. Minga sends zero analytics or crash telemetry; network traffic goes only to the model routes, MCP servers, and language servers you configure. API keys resolve from environment variables first or save locally in ~/.config/minga/credentials.json (0600 permissions), never logged and never exported in transcripts.
  • Corporate gateway & binary transparency. Teams can route exclusively through an internal proxy using MingaAgent.InferenceRoute rather than public provider endpoints. Rolling macOS desktop builds are Apple Developer ID signed and notarized, and the entire codebase is MIT open source and buildable from source.
  • Why compiled extension updates activate on restart (ADR-0003). While SPC h r reloads options, bindings, hooks, and advice in place, compiled extension packages can own supervisors, closures, and dependencies that cannot atomically cross a version boundary mid-session. Disabling an extension takes effect immediately; updated extension code activates cleanly on restart.
