EXTENDING Three Layers

Extending Minga

Elixir configures every layer of Minga, from five lines in config.exs to supervised packages and corporate LLM gateways.

1. Three layers 2. config.exs 3. Extensions, hooks & gateways 4. Task workflows (v0.1.0) 5. Security & reloads

1. One language across three layers

Every layer shares one Elixir runtime over Minga's buffers, drawers, and key scopes, trading OS-level plugin sandboxing and hot-patching of compiled packages (ADR-0003) for unified programmability:

  • Layer 1 · config.exs Reloads live (SPC h r). Typed options, keybindings, custom commands, save hooks, and advise command wrappers.
  • Layer 2 · Extensions Supervised packages (minga_sdk). Hex, Git, or local packages for supervisors, custom buffers, corporate LLM routes, and runtime grammars.
  • Layer 3 · Task workflows v0.1.0 roadmap. Author readable Elixir workflows over buffers and agents, activate under a revocable grant, then discard or reuse.

2. Layer 1: Everyday customization in config.exs

~/.config/minga/config.exs is plain Elixir with typed validation. Hooks run in background processes; command wrappers catch exceptions.

~/.config/minga/config.exs Elixir 
use Minga.Config

set :theme, :catppuccin_frappe
set :line_numbers, :hybrid
set :scroll_margin, 6

# Per-filetype option overrides take a plain keyword list.
for_filetype :go, tab_width: 4, indent_with: :tabs

# Background save hooks run in separate processes and never stall typing.
on :after_save, fn _buf, path ->
  if String.ends_with?(path, ".go") do
    System.cmd("gofmt", ["-w", path])
  end
end

# Wrap any built-in command with :before, :after, :around, or :override advice.
advise :after, :save, fn state ->
  Minga.API.message("Saved")
  state
end

# Install supervised extensions from Hex, Git, or local paths (with optional lazy loading).
extension :minga_git_extended, hex: "minga_git_extended", version: "~> 0.1"

See the Configuration Reference for every typed option, theme token, formatter override, hook, and MCP server setting.

3. Layer 2: Supervised extensions and integration seams

Build a minga_sdk package when a customization needs its own supervision tree, custom buffer surface, or Git/Hex distribution. Disabling an extension tears down all registrations cleanly, and users can override load_policy (:eager, :deferred, {:on_command, [...]}) in config.exs without forking.

lib/my_extension.ex · minga_sdk Elixir 
defmodule MyExtension do
  use Minga.Extension.Editor

  option :enabled, :boolean, default: true, description: "Enable extension"

  command :run_check, "Run custom project check",
    execute: {MyExtension.Commands, :run}

  keybind :normal, "SPC m c", :run_check, "Run custom check", filetype: :go

  @impl true
  def name, do: :my_extension

  @impl true
  def description, do: "Project-specific check runner"

  @impl true
  def version, do: "0.1.0"

  @impl true
  def init(_config), do: {:ok, %{}}
end

Four runtime integration seams

  • Corporate LLM gateways (MingaAgent.InferenceRoute). Stream through an internal proxy in /model while Minga owns approvals, staged overlays, compaction, and history (Model Routes).
  • Deterministic PreToolUse hooks (:agent_hooks). Pipe JSON arguments on stdin with process-group timeouts; non-zero exit blocks the tool and surfaces stderr in chat (Hooks).
  • Crash-isolated MCP (:agent_mcp_servers). Attach stdio MCP servers with prefixed tools (mcp_<server>__<tool>); if one exits mid-turn, only its tools drop out (MCP).
  • Runtime syntax grammars (Minga.Language.register). Compile and cache tree-sitter grammars under ~/.local/share/minga/grammars/ without rebuilding Minga (Grammars).

4. Layer 3: Task workflows (v0.1.0 roadmap)

Between config.exs and a packaged extension, Layer 3 lets you or Minga author a task-specific review surface or check board in readable Elixir over real buffer, drawer, and agent primitives. Inspect the diff, activate under a revocable grant (with rollback on failure), then discard it when the PR lands or reuse it across repos. Pre-v1.0 config or minga_sdk breaking changes are tracked in the Changelog.

5. Security, privacy, and reload boundaries

  • Trust model. Extensions run with your OS-user privileges (like Neovim Lua and Emacs Lisp); BEAM isolation contains crashes, not malicious code.
  • Approvals & updates. Destructive agent tools (edits, deletes, shell, git writes, MCP tools by default) require approval; SPC h e u shows git history before updating extensions; v0.1.0 live authoring requires a revocable grant.
  • Data, keys & proxies. Zero telemetry. Keys resolve from env vars first or save locally in ~/.config/minga/credentials.json (0600), never logged or exported. Route exclusively through an internal proxy via MingaAgent.InferenceRoute; macOS builds are Apple Developer ID signed and notarized.
  • Reloads (ADR-0003). SPC h r reloads options, bindings, hooks, and advice in place; disabling an extension takes effect immediately; compiled extension updates activate cleanly on restart.
