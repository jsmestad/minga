Programmability

Extending Minga

Minga works with any language you write. Like Lua in Neovim or Elisp in Emacs, Elixir is the extension language underneath: start with five lines in config.exs, grow into installable packages, or reshape the workbench for a single task.

1. Three layers 2. config.exs 3. Supervised extensions 4. Disposable & kept workflows 5. Trust & reload boundaries

1. One language across three layers

You never outgrow a JSON schema or jump across an IPC plugin wall when your customization gets serious. The same Elixir runtime that runs the core powers every layer of customization:

  • Layer 1 · config.exs Ships today, live reload (SPC h r). Options, themes, per-filetype rules, keybindings, concurrent lifecycle hooks, and command advice (:before, :after, :around, :override).
  • Layer 2 · Extensions Ships today. Installable packages from local paths, Git repos, or Hex using minga_sdk: declarative commands, custom sidebars, custom model routes, and runtime-compiled syntax grammars.
  • Layer 3 · Task workflows Building for v0.1.0. Write or ask Minga's agent to author readable source over real buffer, agent, and permission owners; Save to activate; discard when a one-off task ends or Keep across projects.

2. Layer 1: Everyday customization in config.exs

~/.config/minga/config.exs is ordinary Elixir with typed option validation. Hooks execute in isolated background processes so a slow formatter or linter never stalls typing, and advice wraps any command cleanly without crashing the editor if your handler raises.

~/.config/minga/config.exs Config 
use Minga.Config

set :theme, :astrodark
set :line_numbers, :hybrid
set :scroll_margin, 6

# Filetype-specific defaults without buffer-local boilerplate.
for_filetype :go do
  set :tab_width, 4
  set :indent_with, :tabs
end

# Hooks run in isolated background processes so slow CLI tools never freeze typing.
on :after_save, fn _buf, path ->
  if String.ends_with?(path, ".go") do
    System.cmd("gofmt", ["-w", path])
  end
end

# Skip formatting when the active buffer still has LSP errors.
advise :around, :format_buffer, fn execute, state ->
  errors =
    state.buffers.active
    |> Minga.Diagnostics.for_buffer()
    |> Enum.count(fn d -> d.severity == :error end)

  if errors == 0, do: execute.(state), else: state
end

# Install supervised extensions from local paths, Git, or Hex.
extension :git_extended, git: "https://github.com/jsmestad/minga-git-extended"

See the Configuration Reference in ExDoc for every typed option, theme token, formatter override, and MCP server setting.

3. Layer 2: Supervised extensions, model routes, and grammars

When a customization needs its own supervision tree, persistent state, sidebar surface, or distribution via Git or Hex, build it with minga_sdk. Every registration is tagged with its source ({:extension, name}), so disabling an extension removes only its commands, keybindings, sidebars, language packs, and UI state without leaking stale entries.

lib/my_extension.ex · minga_sdk Elixir 
defmodule MyExtension do
  use Minga.Extension

  option :enabled, :boolean, default: true, description: "Enable extension"

  command :run_check, "Run custom project check",
    execute: {MyExtension.Commands, :run}

  keybind :normal, "SPC m c", :run_check, "Run custom check"

  @impl true
  def name, do: :my_extension

  @impl true
  def description, do: "Project-specific check runner"

  @impl true
  def version, do: "0.1.0"

  @impl true
  def init(_config), do: {:ok, %{}}
end

Two extension seams worth knowing

  • Custom model routes. Connect an internal company LLM gateway or custom subscription route to /model via MingaAgent.InferenceRoute. Your route only streams model replies; Minga keeps running tool approvals, staged buffer forks, retries, compaction, and session history (Model Routes Reference).
  • Runtime language grammars. Ship tree-sitter grammar sources with an extension via Minga.Language.register/3 and Minga compiles them on demand, caches the shared library in ~/.local/share/minga/grammars/, and wires highlight queries without rebuilding Minga (Tree-Sitter Grammars Reference).

4. Layer 3: Disposable when one-off, kept when it sticks (v0.1.0)

The defining promise of Minga v0.1.0 (#3542 and #3662) is treating your working environment as disposable, task-shaped software.

You do not have to write a full package or fork Minga just to reshape how you review a thorny migration or collaborate on a Markdown spec. Ask Minga's agent (or edit the source yourself) to author a workflow or surface over Minga's existing buffer, agent, and permission owners, save the file to activate it, and inspect the result live. When the task finishes, throw it away if it was one-off, or Keep the shared definition so it stays available across tabs, restarts, and repositories without regenerating it.

Release status

Layers 1 and 2 (config.exs, hooks, advice, installable extensions, model routes, and runtime grammars) ship on main today. Layer 3 (live Save-to-activate definitions, shared composition, and Keep across projects) is the active v0.1.0 milestone gated on #3542 and #3662.

5. Honest trust model and reload boundaries

  • No hidden sandbox claims. Extensions and authored definitions run with OS-user privileges, matching Emacs Lisp and Neovim Lua. Minga isolates extension callback failures so a broken callback cannot crash the editor, and uses explicit session grants for v0.1.0 preparation, but that is failure containment rather than OS-level sandboxing of untrusted code.
  • Why compiled extension updates take effect on restart. While SPC h r reloads options, bindings, hooks, and advice immediately, compiled extension packages can own supervisors, closures, and dependencies that cannot atomically cross a version boundary mid-session. Disabling takes effect immediately; updated extension artifacts activate cleanly on restart (ADR-0003).
