Remote Devboxes, MCP & Safety Guardrails

Shipping real work on proprietary repos means long-running devboxes, deterministic guardrails around shell tools, isolated Model Context Protocol servers, and internal model gateways. Everything in this lesson ships on main today.

1. Headless devboxes & SSH attach 2. PreToolUse veto hooks 3. Crash-isolated MCP servers 4. Corporate gateways & terminal SSH

1. Close your laptop; agents keep working on your devbox

When your source tree and build cache live on a Linux devbox, you should not have to mirror gigabytes locally or keep an SSH terminal glued open while a test suite finishes. Run Minga as a headless daemon on the remote machine and attach from macOS or any terminal whenever you want to inspect or edit.

In headless mode, the Erlang VM boots only buffer, project, and agent services; the editor renderer and syntax parser OS processes do not start until a client attaches.

Remote devbox + local attach 
# 1. On your Linux devbox (keep user services alive after logout):
loginctl enable-linger "$USER"
minga --headless

# 2. From your Mac or another terminal (zero source code copied locally):
minga attach ssh://devbox/work/app

If your team automates sessions from external scripts or dashboards, headless mode also exposes an optional token-gated WebSocket JSON-RPC gateway. Full systemd and launchd unit templates live in the Remote Agents Reference.

2. Deterministic PreToolUse veto hooks

Prompt instructions are advice; shell exit codes are enforcement. Minga lets you wire a local script to run before any matching agent tool call ("shell", "*_file", or "*"). Minga pipes the tool arguments as JSON on stdin, enforces a POSIX process-group timeout so runaway checks clean up cleanly, and blocks the call whenever the script exits non-zero, showing your stderr message straight to the model and in chat.

~/.config/minga/config.exs · PreToolUse registration 
set :agent_hooks, [
  %{
    event: "PreToolUse",
    tool: "shell",
    command: "~/.config/minga/hooks/check-shell-command.sh",
    timeout_ms: 10_000
  }
]
~/.config/minga/hooks/check-shell-command.sh 
#!/usr/bin/env bash
set -euo pipefail

cmd=$(jq -r '.command // ""')

if [[ "$cmd" == *"git push --force"* || "$cmd" == *"rm -rf /"* ]]; then
  echo "Blocked by local safety hook: destructive command not allowed." >&2
  exit 1
fi

Reload your config live with SPC h r and every subsequent shell call passes through your script first. See the Hooks Reference for the full stdin schema and matcher syntax.

3. Crash-isolated multi-server MCP

Model Context Protocol (MCP) servers let agents query GitHub issues, Linear tickets, Postgres schemas, or internal tools. In Minga, each stdio MCP server runs under its own supervised Erlang VM process. If one server hangs or crashes mid-turn, only its prefixed tools (mcp_<server>__<tool>) drop out while your open buffers, undo history, built-in tools, and healthy MCP servers keep going.

~/.config/minga/config.exs · Multiple stdio MCP servers 
set :agent_mcp_servers, [
  %{
    name: "github",
    command: "npx",
    args: ["-y", "@modelcontextprotocol/server-github"],
    env: %{"GITHUB_PERSONAL_ACCESS_TOKEN" => System.fetch_env!("GITHUB_TOKEN")}
  },
  %{
    name: "postgres",
    command: "npx",
    args: ["-y", "@modelcontextprotocol/server-postgres", System.fetch_env!("DATABASE_URL")]
  }
]

By default, MCP tools are treated as destructive and require explicit approval (y once, a session, t turn, n deny). Notice the pattern above: read tokens from shell environment variables via System.fetch_env!/1 so secrets never land in your dotfiles. See the MCP Reference for per-server options.

4. Corporate gateways, credentials, and terminal parity

For company laptops and regulated environments, Minga keeps its network and credential surface small and auditable:

  • Internal LLM proxies (MingaAgent.InferenceRoute): Write a small Elixir extension implementing MingaAgent.InferenceRoute to route requests through your company's gateway or private endpoint. Your route only streams model responses; Minga keeps owning staged overlays, tool approvals, retries, compaction, and crash-safe session recovery (Model Routes Reference).
  • Zero telemetry & local credentials: Minga sends zero analytics or crash telemetry. Prefer exported environment variables or an internal gateway on work machines; keys saved via /auth are written locally to ~/.config/minga/credentials.json with 0600 permissions and excluded from logs and session exports.
  • Retained shell logs across restarts: Long test outputs stay saved on disk beyond the 51 KiB model preview so you can inspect full failures after compaction or restarts, and every tool call is recorded before execution so crashes never silently replay side effects (Session Recovery Reference).
  • Terminal capabilities over SSH: The Go terminal client uses modern protocols where available (Kitty keyboard disambiguation, OSC 52 clipboard over SSH, mode 2026 synchronized output) and degrades quietly down to 16-color terminals.
