Learn / Lesson 05 of 05 · Leave an agent unattended

Leave an agent working while you are away

The agent is halfway through a task and you want to close the laptop. By default Minga asks you before each shell command, so an agent nobody is watching waits at the first one. Tell Minga to stop asking, and nothing stands between the agent and git push --force. A hook is the rule that stays: a short script Minga runs before every shell command the agent asks for, and when the script says no, the command does not run. Test the one below, then install it.

check-shell-command.sh · the hook the tester reads its rules from 
#!/bin/sh
# Minga runs this before each shell command the agent asks for.
# Exit 0 and the command goes ahead. Any other exit stops it.

# Minga sends the request as JSON on stdin. jq reads the command out of it.
cmd=$(jq -r '.arguments.command // ""') || {
  echo "check-shell-command.sh could not read the command. Is jq installed?" >&2
  exit 1
}

# block_if PATTERN REASON: stop the command when the pattern matches it.
block_if() {
  if printf '%s\n' "$cmd" | LC_ALL=C grep -Eiq -- "$1"; then
    echo "Blocked by your hook: $2" >&2
    exit 1
  fi
}

block_if '(^|[^a-z])git +push( [^;&|]*)? (-f|--force)' 'force push'
block_if '(^|[^a-z])rm +-(rf|fr) +"?(/|~|\$HOME)[/*]*([^a-z0-9._/*-]|$)' 'recursive delete of / or your home directory'

exit 0

The tester runs in your browser. It reads its two rules from the script printed beside it, so the rules you test are the rules you copy.

01 The hook

What the hook blocks, and what happens next.

A hook is a shell command you name in your Minga config. This one is for PreToolUse, the moment before a tool runs. A tool is one kind of action the agent can take, and shell is the tool that runs commands. Before each shell call, Minga starts your script and writes a small JSON description of the call to its input. The script reads the command from arguments.command and answers with its exit code: 0 lets the call run, and any other number stops it (Hooks).

The two rules

Each block_if line holds a pattern and the reason the hook prints. A pattern is a regular expression, a compact way to describe text. Both rules ignore upper and lower case and allow extra spaces.

  • Force push. git push followed by -f or by any option that starts with --force. That includes --force-with-lease, on purpose: an agent nobody is watching should not rewrite a shared branch.
  • Recursive delete of / or your home directory. rm -rf or rm -fr aimed at /, ~ or $HOME, and at nothing longer. rm -rf ./build passes, and so does rm -rf /tmp/prod.

When the hook says no

  • Minga does not run the command. It ignores what the script printed to standard output and shows what it printed to standard error as an error in the chat. The agent gets the refusal as the result of the call and carries on with its turn.
  • The hook runs on every shell call, whether Minga asked you first or you told it to stop asking.
  • A hook that fails also stops the command. If the script is missing, is not marked as runnable, or cannot find jq, it exits with a number other than 0, and Minga treats that as a no.
  • A hook that takes too long also stops the command. The limit is 30 seconds unless you set timeout_ms. When it passes, Minga ends the script and shows an error in the chat.

02 Limits

What this hook does not catch.

The hook reads the text of a command. It does not know what the command will do. A pattern hook is a seat belt, not a sandbox: it misses the same damage written another way, and it stops a harmless command that only mentions a blocked one.

  • Another spelling gets through. git push origin :main deletes the branch on the server with no --force at all. rm -r -f / splits the options, so the second rule does not match it.
  • A script hides the command. If the agent writes cleanup.sh and runs it, the hook sees sh cleanup.sh and nothing inside the file.
  • A mention is enough to block. echo "rm -rf /" deletes nothing, and the hook stops it anyway. The agent gets the reason and can word the command another way.
  • Other paths are yours to add. The second rule names / and your home directory. If /tmp/prod matters to you, write a rule for it, and test it above the way you tested these.
  • Minga's own limits still apply. A shell command runs in a temporary copy of your project with the staged edits applied. A command that names a path outside that copy can still write there, and the copy shares the project's deps directory and its installed node_modules packages. The agent's Git stage and commit tools act on your real repository. Architecture lists these limits.

03 Install

Install the hook, then stop being asked.

Three steps, in this order. The hook goes in first, so there is no time when the agent runs shell commands with no rule and no question.

  1. Save the script and make it runnable. The second line opens the file in your editor; paste the script from the top of this page into it and save. The third line, chmod, marks that file as a program. The script needs jq, a small program that reads JSON; install it with your package manager, for example brew install jq or sudo apt install jq.

    Terminal 
    mkdir -p ~/.config/minga/hooks
"${EDITOR:-vi}" ~/.config/minga/hooks/check-shell-command.sh
chmod +x ~/.config/minga/hooks/check-shell-command.sh

  2. Tell Minga to run it. Add this to ~/.config/minga/config.exs, below the use Minga.Config line the file starts with. Then restart Minga, which reads the file when it starts. event names the moment, tool names the tool the hook applies to, and timeout_ms gives the script ten seconds to answer.

    ~/.config/minga/config.exs 
    set :agent_hooks, [
  %{
    event: "PreToolUse",
    tool: "shell",
    command: "~/.config/minga/hooks/check-shell-command.sh",
    timeout_ms: 10_000
  }
]

  3. Check the real file, then trust the shell tool. Send the script the same JSON Minga sends. The first line below must end with exit 1 and the second with exit 0. After that, the next time Minga asks you about a shell command, trust the shell tool for the rest of the session: use the approval card's button, or leave the composer and press a. The agent stops waiting for you, and the hook still runs on every call.

    Terminal 
    echo '{"arguments":{"command":"git push --force origin main"}}' | ~/.config/minga/hooks/check-shell-command.sh; echo "exit $?"
echo '{"arguments":{"command":"npm test"}}' | ~/.config/minga/hooks/check-shell-command.sh; echo "exit $?"

04 Remote

Close the laptop and the work keeps going.

An agent that runs on your laptop sleeps when the laptop does. Run Minga on a machine that stays on, and your laptop becomes a window you can close. The agent, your config and your hook all live on that machine, so install the hook there (Remote Agents).

Remote machine once, then your laptop 
# Once, on the remote Linux machine, from a checkout of the Minga repository.
mkdir -p ~/.config/systemd/user
cp rel/systemd/minga-headless.service ~/.config/systemd/user/
# Set ExecStart, WorkingDirectory, RELEASE_COOKIE and your provider key before the service starts.
"${EDITOR:-vi}" ~/.config/systemd/user/minga-headless.service
systemctl --user daemon-reload
systemctl --user enable --now minga-headless.service
loginctl enable-linger "$USER"

# Each time, on your laptop, with the same RELEASE_COOKIE in your environment.
minga attach ssh://devbox/work/app
  • The first half installs Minga as a service, a program the system starts and keeps running with no window. The service file comes from the Minga repository, so run these lines in a checkout of it. The file ships with a placeholder password, which is why the block opens it in your editor before anything starts. loginctl enable-linger tells Linux to keep your services running after you log out. A remote Mac uses a different service file; Remote Agents has those steps.
  • RELEASE_COOKIE is a shared password: one long random value, at least 32 random bytes, that the remote machine and your laptop both hold. Anyone who has it can control the remote Minga, so keep the machine on a private network.
  • minga attach uses SSH to start that service if it is not running, then opens the agent session for /work/app on the machine named devbox. The project stays on the remote machine. Minga does not copy your source code to the laptop.
  • To leave, close the laptop, or run minga detach to disconnect and keep the laptop open. Either way the agent's turn keeps running.

05 Tonight

What you can do differently tonight.

Before this lesson, leaving an agent alone meant one of two things: it waited for an answer, or it ran every command it liked. Now there is a third way. Save the script, add the config, check the real file with the two test lines, and trust the shell tool for the session. Then give the agent its task and walk away. When a new worry comes up, write one more block_if line and test it here first.

If your agent also uses tools from an MCP server, a separate program that gives it extra tools such as access to GitHub, Minga asks before running those too unless you allow them one by one; MCP has the setup.
