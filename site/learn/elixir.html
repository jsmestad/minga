Learn / Lesson 03 of 04 · Translate a setting

Bring one setting from your old config

Your Neovim, Emacs or VS Code config has a line that picks your color theme, and you want the same theme here. In Minga that is one line in one file, and it applies when you reload, with no restart. Pick your editor, find the setting, and take the line with you.

Find your line Build the file What you can do now

Minga keeps its settings in one file, ~/.config/minga/config.exs. The file is written in Elixir, a programming language, and you do not need to learn it first. The four settings below use three words: set changes an option everywhere, for_filetype changes it for one language, and bind puts a command on a key.

1 Pick the editor your config is in.

2 Select a setting to read what each part of the Minga line means.

  • Neovim · init.lua, with the catppuccin plugin

    vim.cmd.colorscheme("catppuccin-latte")

    Emacs · init.el, with the catppuccin-theme package

    (setq catppuccin-flavor 'latte)
(load-theme 'catppuccin :no-confirm)

    VS Code · settings.json, with the Catppuccin extension

    "workbench.colorTheme": "Catppuccin Latte"

    Minga · config.exs

    set :theme, :catppuccin_latte

    set changes one option everywhere. :theme is the option and :catppuccin_latte is its value. A word with a colon in front is an atom: a fixed name that Minga knows, written without quotes.

    The other three editors get Catppuccin from a plugin. Minga has it built in. It starts on :catppuccin_frappe, a dark theme from the same family, so this line switches you to the light one.

  • Neovim · init.lua

    vim.api.nvim_create_autocmd("FileType", {
  pattern = "go",
  callback = function()
    vim.bo.tabstop = 8
    vim.bo.shiftwidth = 8
  end,
})

    Emacs · init.el, with go-mode

    (add-hook 'go-mode-hook
          (lambda () (setq-local tab-width 8)))

    VS Code · settings.json, with the Go extension

    "[go]": {
  "editor.tabSize": 8
}

    Minga · config.exs

    for_filetype :go, tab_width: 8, indent_with: :tabs

    for_filetype changes options for one language. :go names the language. tab_width: 8 is an option name, a colon, and its value. Elixir calls a run of these name-and-value pairs a keyword list, and this line has two of them, with a comma between.

    The second pair is there because the other three editors already indent Go with tabs, and Minga indents with spaces until you tell it indent_with: :tabs. With both pairs, a tab is one character drawn 8 columns wide. Without the line, Go files use the width you set for every language, which is 2 unless you change it.

  • Neovim · init.lua, with a Go language server

    vim.api.nvim_create_autocmd("BufWritePre", {
  pattern = "*.go",
  callback = function()
    vim.lsp.buf.format()
  end,
})

    Emacs · init.el, with go-mode

    (add-hook 'before-save-hook #'gofmt-before-save)

    VS Code · settings.json, with the Go extension

    "[go]": {
  "editor.formatOnSave": true
}

    Minga · config.exs

    for_filetype :go, format_on_save: true

    true and false are written as they are, with no colon and no quotes. With this line, Minga formats a Go file before it writes it: with gopls, Go's language server, when it is running, and with gofmt otherwise.

    If the file cannot be formatted, for example because of a syntax error, Minga does not save it and the status line reads "Save skipped: formatter failed". Fix the error and save again. If gofmt is not installed and gopls is not running, Minga saves the file unformatted and tells you the formatter is missing.

    This row and the one above both change Go, so in your file they can share a line: for_filetype :go, tab_width: 8, indent_with: :tabs, format_on_save: true.

  • Neovim · init.lua

    vim.keymap.set("n", "<leader>fw", "<cmd>write<cr>", { desc = "Save file" })

    Emacs · init.el

    (global-set-key (kbd "C-c w") #'save-buffer)

    VS Code · keybindings.json

    [
  {
    "key": "ctrl+alt+w",
    "command": "workbench.action.files.save"
  }
]

    Minga · config.exs

    bind :normal, "SPC f w", :save, "Save file"

    bind puts a command on a key. It takes four things in order: the mode the key works in (:normal is the mode for moving around, as opposed to typing text), the keys, the name of the command, and a label that Minga shows in its key hints. Text inside double quotes is a string: Minga reads it exactly as written. SPC stands for the space bar, so this key is space, then f, then w.

    Each editor has its own spare keys, so the key differs from editor to editor. The command is the same in all four: save the file. To find the name of any command, press SPC h a and type what it does.

01 Your file

Build the file, paste it, reload.

The file's first line, use Minga.Config, makes set, for_filetype and bind available, so keep it at the top.

Choose the values you want. The file changes as you choose, and the small preview above it shows the theme, the line numbers and the Go tab width.

This is the file with the lesson's starting values. With JavaScript on, you can change the values here before you copy it.

Preview · Catppuccin Frappé wait.go
1func wait(n int) int {
0 ms := 250 * n
1 return min(ms, 30000)
2}
~/.config/minga/config.exs 
use Minga.Config

set :theme, :catppuccin_frappe
set :line_numbers, :relative

for_filetype :go, tab_width: 8, indent_with: :tabs, format_on_save: true

Copied. Three steps are left, and they happen in Minga. The browser did not allow the copy. Select the text of the file and copy it yourself.
  1. In Minga, open any file first: with no file open, the next key does nothing. Then press SPC f p (Space, then f, then p). It opens ~/.config/minga/config.exs, and creates the file if you do not have one.
  2. Paste the text over what is there, or add only the lines you want below use Minga.Config. Save with SPC f s.
  3. Press SPC h r. The status line reads "Config reloaded".

The theme and the line numbers change at once, in the files you already have open. The Go line takes effect in Go files you open after the reload. If you have changed the theme or the line numbers in the macOS app's Settings, that choice wins over this file. A key of your own, such as the one in the fourth row above, goes on a line of its own in the same file.

02 After this

What you can do now.

You can read a line of Minga config and say what each part does, so you can move the rest of your settings one line at a time, or check a config that an agent wrote for you. The same three words reach every option in the configuration guide.
