# Frontend conformance transcript corpus

This corpus makes frontend parity a test, not a document (#2667). It is a shared set of transcripts that the Swift (`macos/Tests/MingaTests/ConformanceTranscriptTests.swift`) and Go (`go/tui/internal/ui/conformance_transcript_test.go`) suites enumerate in CI. Shared behavior runs on both frontends; native-only behavior has an explicit skip reason rather than a claim of terminal parity.

The transcripts cover resident stores, input resolution, agent chat, and native keyboard ownership. They encode the window and reconciliation contracts in `docs/GUI_PROTOCOL.md` and the focus contract in [ARCHITECTURE.md](../../../docs/ARCHITECTURE.md#frame-transactions).

## Do not hand-edit

Every JSON file here is generated by `mix conformance.gen`, which drives the **real** GUI adapter encoders and render models. Window bytes come from `WindowEncoder`, agent chat from `AgentTranscriptEncoder`, and keyboard ownership from `FocusOwnerEncoder`. Regenerate after any encoder or contract change:

```bash
mix conformance.gen
```

Because payload bytes come from the real encoders, fixtures cannot drift from the wire format (AC4). Window and chat expectations follow the render models and documented reconciliation rule. Focus expectations follow the named owner and native lifecycle contract. There are no hand-typed wire bytes, including the negative (ref-miss) case, which is produced by encoding a delta that references an unretained row.

Fixtures are deterministic: no timestamps, no randomness. Row identities come from `Row.stable_id/4` and content hashes from `Row.compute_hash/2`, both pure.

## Layout

```
test/conformance/corpus/
  index.json          # enumerates every transcript + which frontends run it
  README.md           # this file
  store/*.json         # store-lifecycle transcripts (AC1)
  input/*.json         # input-resolution transcripts (AC2)
  chat/*.json          # resident agent-transcript transcripts (0x86, #2654)
  focus/*.json         # ten native lifecycle (#3512) and seven shared owner (#3518) transcripts
```

| Category | Contract | Swift | Go |
|----------|----------|-------|----|
| `store` | Resident window lifecycle and production render boundaries | Runs | Runs |
| `input` | Pointer normalization and local scroll reconciliation | Runs | Runs supported seams; index declares skips |
| `chat` | Resident agent transcript updates and reading position | Runs | Runs |
| `focus` (native-only) | Committed keyboard owner through native lifecycle events (#3512) | Runs against AppKit harness | Explicit skip for each of ten named entries |
| `focus` (shared) | BEAM-derived owner through real encoded frame transactions (#3518) | Pure resolver plus separate production ContentView replay | Runs all seven entries against committed component resolution |

`index.json` is the enumeration authority. A frontend that cannot yet run a transcript must skip it *by name from this list* (a skipped-but-enumerated transcript is the deliverable); silent omission is not allowed.

```json
{
  "version": 1,
  "transcripts": [
    { "name": "...", "category": "store|input|chat|focus", "file": "store/....json",
      "swift": true, "go": true|false, "go_skip_reason": null | "..." }
  ]
}
```

## Transcript format

Each transcript file is one JSON object:

```json
{
  "name": "keyframe_decode",
  "category": "store",
  "description": "human-readable summary of the seam under test",
  "frontends": { "swift": true, "go": true, "go_skip_reason": null },
  "steps": [ ... ]
}
```

`frontends.go = false` with a `go_skip_reason` marks a capability the Go TUI does not implement. The runner enumerates and explicitly skips each such transcript with its declared reason. This includes resident scroll seams and AppKit keyboard ownership; it does not imply that Go has executed the native lifecycle.

### Steps

Steps run in order against the relevant frontend state. Window and input transcripts use three kinds:

1. **frame** — a single framed binary opcode message produced by the real encoder. The runner base64-decodes `payload_base64`, decodes it through the frontend's real protocol decoder, applies it through the real store/dispatch path, then checks `expect`.

   ```json
   { "kind": "frame", "opcode": 128, "note": "keyframe",
     "payload_base64": "...", "expect": { ... } }
   ```

   `opcode` is informational (128 = 0x80 keyframe, 160 = 0xA0 overlay delta, 161 = 0xA1 viewport delta, 162 = 0xA2 rows delta).

2. **inject_offset** — state injection. Sets a nonzero local presentation offset on a window *mid-transcript*, using anchor keys that match the currently-stored frame. This is the whole point of the input suite: store-state-only transcripts were ruled insufficient, so the runner must be able to run a transcript against a frontend whose local offset is nonzero.

   ```json
   { "kind": "inject_offset", "window_id": 1, "row_offset": 3, "col_offset": 0 }
   ```

3. **pointer** — a pointer (drag) event at a content-relative row/col. The runner normalizes it through the frontend's **real** presentation offset transform (Swift `clampPresentationPoint`/`presentationScrollOffset`, Go `normalizePresentationMouse`) and checks the resulting buffer line.

   ```json
   { "kind": "pointer", "window_id": 1, "pointer_row": 2, "pointer_col": 3,
     "expect": { "normalized_buffer_line": 45 } }
   ```

### Chat steps (resident agent transcript, 0x86, #2654)

The `chat/*.json` family is a distinct transcript shape for the resident agent-chat transcript stream (`gui_agent_transcript`, 0x86). Its frames are produced by the real `Minga.Frontend.Adapter.GUI.AgentTranscriptEncoder` and folded through each frontend's real store apply (Swift `AgentChatState.applyTranscript`, Go `residentTranscript.apply`), so an encoder change regenerates the corpus and drift is caught. A third leg, the BEAM oracle in `test/conformance/agent_transcript_corpus_test.exs`, re-decodes the same bytes and asserts they carry exactly what the expectations claim.

There are three chat step kinds:

1. **transcript_frame** — a single framed 0x86 message. The runner base64-decodes `payload_base64`, decodes it through the real protocol decoder, applies it through the real resident store, then asserts `expect.transcript` (the shared parity core, asserted identically on both frontends and the BEAM oracle).

   ```json
   { "kind": "transcript_frame", "opcode": 134, "note": "full_replace 8 messages",
     "payload_base64": "...",
     "expect": { "transcript": { "epoch": 1, "count": 8, "truncated": false, "message_ids": [1,2,3,4,5,6,7,8] } } }
   ```

2. **transcript_scroll** — a local scroll input (`rows`, signed: `+`down / `-`up). Go owns a top-anchored scroll offset in the store, so its runner drives the real `scrollBy` + `resolveScroll` and asserts the `go` selector. Swift's scroll is a SwiftUI `ScrollView` concern with no store effect, so its runner treats this step as a no-op (position preservation is asserted via id stability instead).

   ```json
   { "kind": "transcript_scroll", "note": "scroll up 4 rows", "rows": -4,
     "go": { "max_top": 6, "expect_top_offset": 2, "expect_pinned": false, "expect_pin_transition": "scrolled_away" } }
   ```

3. **transcript_assert** — a per-frontend position-preservation assertion. `swift` asserts the id at a store index (`ForEach(id:)` stability is what preserves the SwiftUI scroll position across an append). `go` drives `resolveScroll` at the post-frame `max_top` and asserts the reading offset is stable and the pin state is correct.

   ```json
   { "kind": "transcript_assert", "note": "reading position preserved",
     "swift": { "anchor_index": 2, "anchor_id": 3 },
     "go": { "max_top": 7, "expect_top_offset": 2, "expect_pinned": false } }
   ```

Both frontends run every chat transcript; there are no `go_skip` entries in this family. The per-frontend `swift`/`go` selectors capture the honest asymmetry between the two offset models (SwiftUI id stability vs. a store-owned top-anchored offset), while the shared `transcript_frame.expect.transcript` is what makes the resident-store parity executable. `expect_top_offset` and `expect_pin_transition` are optional (an unpinned-only or pin-only assertion omits the irrelevant key). Pin transition names are `scrolled_away`, `returned`, or absent (no edge).

### Focus steps (native keyboard ownership, 0xAA, #3512)

A picker that owns the keyboard must keep it when its window becomes key or a file drop finishes. The ten native-only focus transcripts make that promise executable instead of checking only that the owner decoded. The Swift runner creates `FocusConformanceHarness` only for entries whose category is `focus` and whose actual consumer designation is `go: false`. It uses a real offscreen `NSWindow`, real views and fields, and the production `EditorFocusPolicy`. It checks the window's actual `firstResponder`, including an `NSTextField`'s active field editor. It does not assign the expected responder itself.

Native-only focus transcripts use ordinary **frame** steps containing a real `FocusOwnerEncoder` command (`gui_focus_owner`, opcode 170), followed by **native_event** steps. Each native-only focus payload includes production-encoded `begin_frame`, a complete theme, the focus command, and `commit_frame`. The runner dispatches those decoded commands through the production transaction boundary and requires an accepted commit before checking the responder. Other corpus categories keep their existing apply path. Each generated native-only focus frame uses a fresh encoder cache, so its keyframe case emits the same owner twice rather than accidentally testing an omitted command.

```json
{
  "kind": "native_event",
  "event": "agent_overlay_visibility_changed",
  "note": "show the agent overlay",
  "args": { "visible": true },
  "expect": { "first_responder": "editor_view" }
}
```

Each event invokes the corresponding public policy method. Deferred retries settle before the runner asserts `expect.first_responder`. Unknown events fail instead of being ignored.

| Event | `args` | Policy entry point |
|-------|--------|--------------------|
| `window_did_become_key` | `{}` | `windowDidBecomeKey()` |
| `native_modal_began` | `{}` | `beginNativeModal()` |
| `native_modal_ended` | `{}` | `endNativeModalAndRestore()` |
| `native_modal_restored` | `{}` | `restoreAfterNativeModal()` |
| `swiftui_hierarchy_rebuilt` | `{}` | `swiftUIUpdateDidOccur()` |
| `file_drop_completed` | `{}` | `fileDropDidComplete()` |
| `pointer_returned` | `{}` | `pointerReturnedToEditor()` |
| `agent_overlay_visibility_changed` | `{"visible": true\|false}` | `agentOverlayVisibilityDidChange(_:)` |
| `local_text_editing_began` | `{"kind": "workspace_rename"\|"workspace_icon_search"}` | `beginLocalTextEditing(_:)` |
| `local_text_editing_ended` | Same lease `kind` as begin | `endLocalTextEditing(_:)` |
| `native_text_editing_ended` | `{}` | `nativeTextEditingDidEnd()` |
| `responder_registered` | `{"kind": "picker_query"\|"search_query"\|"inline_edit"}` | `register(_:as:)` |
| `responder_unregistered` | Same responder `kind` | `unregister` |
| `first_frame_rendered` | `{}` | `firstFrameDidRender()` |

`expect.first_responder` is one of `editor_view`, `picker_query`, `search_query`, `inline_edit`, or `local_text_field`. Both frame and native-event steps carry it. The last name means a frontend-local SwiftUI text field, not a new BEAM surface. Lease-begin events host a real field driven by the policy's published focus mirror; lease-end events end native editing, remove that host, and release the matching lease. Native-text-end events finish AppKit editing before notifying the policy.

Responders are registered at setup unless a transcript declares otherwise:

```json
"setup": { "unregistered_responders": ["inline_edit"] }
```

Only the late-registration transcript uses that metadata. It establishes `editor_view` first, then commits an inline owner whose field is missing. That frame must leave the editor focused; `responder_registered` must apply the pending inline owner without another frame. Later unregister/register steps remove an inactive field, avoiding an unrelated AppKit fallback-responder assertion.

Every native-only focus entry declares `swift: true`, `go: false`, and the exact reason `"no native responder chain; keyboard owner is BEAM-routed"`. The Go runner emits `skipped for Go: <reason>` for each named entry. Its skip-reason test requires every Go-disabled transcript, in every category, to explain the skip. The seven shared focus entries below are not skipped and never instantiate this bare native harness.

The Swift lifecycle coverage guard compares the public policy entry points with the corpus event coverage and an explicit infrastructure/query exclusion list. Adding a lifecycle method without exercising it is a test failure. Focus assertion failures identify the transcript, step index, expected responder, and actual responder on one line.

### Shared focus frames (#3518)

The seven shared `focus/` entries, selected by their actual `go: true` consumer designation, use `kind: "framed"`: `payload_base64` is the complete raw wire batch, including `begin_frame` and `commit_frame`, without the outer packet4 length. `command_sizes` records encoder-produced command boundaries for the BEAM oracle. Consumers decode the batch with their production decoder and dispatch the transaction, not the test-only unframed mutator.

Each shared step carries `expect.focus_target = {surface, responder, window_id, generation}`, derived by the existing `MingaEditor.FocusOwner.derive/1` over the scenario's editor state. The same owner is encoded by the production semantic adapter. Swift asserts the pure `FocusResolution`; Go resolves the committed focused component and checks the retained wire responder and source generation. Every shared focus transcript runs on both consumers. The additional production `ContentView`/`NSWindow` replay is macOS-specific, separate from the native-event harness above.

A framed step may set `reset_frontend: true` (otherwise false). Before decoding that step, discard the entire frontend consumer and its local presentation state. The producer's editor state is not reset. The reattach scenario marks its third step this way: the real encoder sends a keyframe while the picker remains open, but Swift and Go must recover its owner into fresh stores. The native replay destroys the previous window, GUI state, policy, and registered hierarchy, then hosts a fresh production `ContentView` before applying that same keyframe. The BEAM oracle clears its retained consumer owner before consuming the keyframe's encoded fact.

Responder waits only observe the production hierarchy and first responder while yielding the runloop; they never call focus policy hooks, force layout, or reapply an owner to make an assertion pass. Explicit native lifecycle replay runs separately after each frame has established its own responder and AX identity. First-frame notification occurs only once per fresh consumer.

Scenarios cover picker open-close with an unchanged delta, native search open-close, file-tree rename confirm and cancel, agent toggle, a reattach keyframe while the picker owns focus, focused hover, and the empty launchpad. Rename transcripts exercise the admitted edit lifecycle; filesystem rename effects remain covered by the file-tree workflow tests. Agent input uses the editor responder and BEAM `agent` scope, not a new native field. Generations retain their source meaning: picker activation generation or file-tree edit token, and zero where there is no source generation.

Regenerate with `mix conformance.gen` after compilation and dependencies are available. Run the BEAM leg with `mix test.llm test/conformance/focus_corpus_test.exs test/minga_editor/focus_owner_test.exs`, and Go with `cd go/tui && go test ./internal/ui -run TestConformanceTranscripts`. On macOS, run `ConformanceTranscriptTests`, `FocusReplayWindowTests`, `FocusResolutionTests`, `FocusWriterGuardrailTests`, `EditorFocusPolicyTests`, `GUIObservationGuardrailTests`, and `GUIFrameSwiftUIInvalidationTests` in the existing `MingaTests` CI job. The window replay checks first responder unconditionally and AX identity when the app is active and its window is key. The signed-app Accessibility workflow remains an on-device smoke, not a prerequisite for these in-process tests.

### `expect` fields

A runner asserts only the keys present on a step; absent keys are not checked.

| Field | Meaning |
|-------|---------|
| `store_present` | Whether the resident window still exists after this frame (false = dropped, e.g. after an unresolvable ref). |
| `rows` | Ordered resident rows, each `{ "row_id": "<u64 as string>", "content_hash": <u32>, "buf_line": <u32> }`. `row_id` is a string to preserve full u64 precision through JSON. |
| `anchor` | `{ "top": <line>, "left": <col> }`, the committed viewport anchor from the current `ScrollPresentation`. |
| `cursor_row` | The window's current cursor display row. |
| `offset_discarded` | Whether applying this frame forced the frontend to discard its local offset (the real reconciliation decision). |
| `normalized_buffer_line` | (pointer steps) `anchor_top + normalized_content_row` after the offset transform. |
| `first_responder` | (focus frames and native events) Actual native responder identity, resolving an active field editor back to its owning field. |
| `focus_target` | The committed BEAM owner `{surface, responder, window_id, generation}`, checked through the frontend resolver. |

A `production_fixture` step is the compact production-size form. Its `fixture` object defines deterministic carrier sizes, row counts, edit coordinates, epochs, and generations; `operations` defines shared expected statuses and row-operation counts. It intentionally has no `payload_base64`: each client expands the same descriptor through its real resident store so repeated multi-megabyte JSON is never checked in.

## What each transcript covers

Store lifecycle (AC1):

- **production_render_boundaries** — compact descriptor expanded by BEAM, Swift, and Go into exactly 65,536 resident rows and one 65,536-byte text carrier. The shared operation transcript covers an ordinary edit, a structural insertion near row zero, retained reference and miss, stale content epoch, stale recovery generation, and reset/full recovery. The checked-in JSON stays near 1 KiB; clients deterministically expand it in memory and assert the same statuses and semantic row-operation counts.
- **keyframe_decode** — 0x80 keyframe decodes to a resident row set keyed by `row_id + content_hash`, with the committed anchor.
- **rows_delta_ref_resolution** — 0xA2 resolves retained refs by `row_id + content_hash` alongside one full row.
- **ref_miss_full_recovery** — a 0xA2 ref to an unretained row drops the window; the next 0x80 recovery frame rebuilds it.
- **cursor_only_overlay_delta** — 0xA0 moves the cursor without touching rows or the anchor.
- **layout_generation_full_replace** — a `layout_generation` change mismatches the anchor key, discarding the offset and replacing rows.
- **reset_required_discard** — a `reset_required` (full_refresh) frame discards the local offset.

Input resolution seams (AC2):

- **drag_selection_active_offset** — a drag pointer under a nonzero local offset normalizes to the visually-correct buffer line.
- **hml_after_scroll_report** — an H/M/L echo commit (same anchor, same `scroll_seq`) moves only the cursor and keeps the offset (no re-anchor storm).
- **scroll_seq_strictly_newer_discard** — a strictly-newer `scroll_seq` with an identical anchor key forces a discard (Go-skipped: windowed contract).
- **same_top_jump_discards** — an authoritative jump (zz already centered, a search hit already on screen) lands on the previous top but still bumps `scroll_seq` via the explicit authoritative-scroll marker, so the frontend discards its local offset (#2652).
- **wheel_momentum_during_ctrl_d** — momentum keeps feeding local offset while ctrl-d's authoritative anchors land on the same top; each `scroll_seq` bump discards the leftover offset (Go-skipped: windowed contract).

Resident agent transcript (0x86, #2654):

- **append_while_scrolled_up** — a bottom append while the reader is scrolled up preserves the reading position: Swift's anchor id stays at its store index, Go's top-anchored offset is unchanged by the growth.
- **pin_to_bottom_resume** — scroll up (unpin, emit the scrolled-away edge), scroll back to the bottom (re-pin, emit the returned edge), then a following append is followed (Go stays pinned; the Swift store's newest message is at the tail the view follows).
- **session_switch_full_replace** — a full_replace at a new epoch resets the resident store to the new session and re-pins to the bottom, discarding the prior local offset.
- **trim_front_eviction_midstream** — streaming past the resident byte cap evicts the oldest messages from the store front (append `trim_front`) and flags the stream `truncated`, instead of degrading to a full_replace per frame.
- **epoch_flip_midstream** — an in-epoch append followed by an epoch flip; the append stays incremental, the epoch flip forces a full_replace even with unchanged messages.
- **streaming_tail_patch** — the streaming last message is patched in place by id (same id, new content); the store stays count 2 with ids [1, 2], catching a frontend that appends instead of upserting.

Native keyboard ownership (0xAA, #3512):

- **picker_focus_survives_window_becoming_key**: activating the window keeps the picker query focused.
- **prompt_returns_to_editor_after_native_modal**: modal end and restoration reapply the prompt's editor responder.
- **inline_edit_survives_swiftui_rebuild**: a SwiftUI update preserves the named inline editor.
- **file_drop_returns_to_named_owner**: drop completion keeps the picker query instead of reclaiming the editor.
- **pointer_return_respects_named_owner**: pointer return respects the search query owner.
- **agent_overlay_toggle_keeps_owner**: showing and hiding agent key routing preserves the committed editor responder.
- **owner_change_deferred_during_local_text_editing**: workspace rename and icon-search leases both defer incoming owners, then apply the latest owner on release.
- **owner_applied_when_responder_registers_late**: a missing inline field leaves ownership pending until registration; unregistering and replacing an inactive field preserves the current owner.
- **keyframe_reasserts_owner**: a fresh-cache keyframe re-emits the unchanged picker owner across first-frame and pointer events.
- **native_text_editing_returns_to_latest_owner**: native field editing holds focus until editing ends, then the pending editor owner applies.
