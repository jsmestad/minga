# Frontend conformance transcript corpus

This corpus makes frontend parity a test, not a document (#2667). It is a shared set of transcripts that the Swift (`macos/Tests/MingaTests/ConformanceTranscriptTests.swift`) and Go (`go/tui/internal/ui/conformance_transcript_test.go`) suites enumerate in CI. Shared behavior runs on both frontends; native-only behavior has an explicit skip reason rather than a claim of terminal parity.

The transcripts cover resident stores, input resolution, agent chat, native keyboard ownership, and closed-loop recovery. They encode the window and reconciliation contracts in `docs/GUI_PROTOCOL.md` and the focus contract in [ARCHITECTURE.md](../../../docs/ARCHITECTURE.md#frame-transactions).

## Do not hand-edit

Every JSON file here is generated by `mix conformance.gen` using the real GUI adapter encoders and render models. Window bytes come from `WindowEncoder`, agent chat from `AgentTranscriptEncoder`, and keyboard ownership from `FocusOwnerEncoder`. The `recovery/` family drives a real editor, `Renderer.Server`, and capturing frontend `Manager`. Regenerate after any encoder or contract change:

```bash
mix conformance.gen
mix conformance.gen --check
```

Because payload bytes come from the real encoders, fixtures cannot drift from the wire format (AC4). Window and chat expectations follow the render models and documented reconciliation rule. Focus expectations follow the named owner and native lifecycle contract. There are no hand-typed wire bytes, including the negative (ref-miss) case, which is produced by encoding a delta that references an unretained row.

Fixtures are deterministic: no timestamps, no randomness. Row identities come from `Row.stable_id/3` and content hashes from `Row.compute_hash/2`, both pure.

`--check` generates the corpus twice, compares those values for determinism, and compares their encoded bytes to the committed files without rewriting them. Recovery driver identities come from scoped generation and epoch allocators and the renderer-owned sequence counter, not normalized copies of nondeterministic wire output. `Renderer.Server` reserves each submission's wire sequence once in mailbox order: the requested sequence is a lower bound, and synchronous receipts report the effective sequence without changing the Editor's independent intent revision. Retries reuse an unissued queued successor's identity or reserve the next counter value; acknowledgements and resets never rewind that counter.

Production renderer replacement gets its starting floor from the surviving Manager's atomic `reserve_recovery_context/1` operation: `{generation, next_frame_seq}` exceeds admitted as well as acknowledged output, revokes retained old frames, and fences subsequent obsolete-generation writes. The Manager derives that floor from its existing ledger; it does not allocate individual frame sequences. The driver's explicit `recovery_reserver` returns the complete deterministic pair instead and never reads ambient Manager state. Later recovery reservations preserve local high-water marks without renumbering a pending attempt.

Each driver owns private keymap and option servers, injected into its real Editor and buffers. Its settings projection uses the canonical built-in scope declarations, so deferred user-extension contributions cannot change the first captured keyframe. The driver does not strip settings commands or rewrite captured payloads. Nondeterminism errors identify the transcript and first differing JSON key.

Startup project-root inference is disabled for the isolated editor, so workspace chrome does not capture the caller's checkout path or race the global Project owner. Settings options are ordered by their string names when the real semantic model is built; VM-specific atom-map iteration is not a protocol ordering contract.

## Layout

```
test/conformance/corpus/
  index.json          # enumerates every transcript + which frontends run it
  README.md           # this file
  store/*.json         # store-lifecycle transcripts (AC1)
  input/*.json         # input-resolution transcripts (AC2)
  chat/*.json          # resident agent-transcript transcripts (0x86, #2654)
  focus/*.json         # ten native lifecycle (#3512) and seven shared owner (#3518) transcripts
  recovery/*.json      # real renderer rejection, timeout, resize and local-input sequences (#3516)
```

| Category | Contract | Swift | Go |
|----------|----------|-------|----|
| `store` | Resident window lifecycle and production render boundaries | Runs | Runs |
| `input` | Pointer normalization and local scroll reconciliation | Runs | Runs supported seams; index declares skips |
| `chat` | Resident agent transcript updates and reading position | Runs | Runs |
| `focus` (native-only) | Committed keyboard owner through native lifecycle events (#3512) | Runs against AppKit harness | Explicit skip for each of ten named entries |
| `focus` (shared) | BEAM-derived owner through real encoded frame transactions (#3518) | Pure resolver plus separate production ContentView replay | Runs all seven entries against committed component resolution |
| `recovery` | Real renderer rejection, targeted replacement, timeout, resize, and local input (#3516) | Runs through production transactions | Runs through production transactions |

`index.json` is the enumeration authority. A frontend that cannot yet run a transcript must skip it *by name from this list* (a skipped-but-enumerated transcript is the deliverable); silent omission is not allowed.

```json
{
  "version": 1,
  "transcripts": [
    { "name": "...", "category": "store|input|chat|focus|recovery", "file": "store/....json",
      "swift": true, "go": true|false, "go_skip_reason": null | "..." }
  ]
}
```

## Transcript format

Each transcript file is one JSON object:

```json
{
  "name": "keyframe_decode",
  "category": "store",
  "description": "human-readable summary of the seam under test",
  "frontends": { "swift": true, "go": true, "go_skip_reason": null },
  "steps": [ ... ]
}
```

`frontends.go = false` with a `go_skip_reason` marks a capability the Go TUI does not implement. The runner enumerates and explicitly skips each such transcript with its declared reason. This includes the macOS accessibility projection and AppKit keyboard ownership; it does not imply that Go has executed the native lifecycle.

### Steps

Steps run in order against the relevant frontend state. The legacy unframed kinds are:

1. **frame** — a single framed binary opcode message produced by the real encoder. The runner base64-decodes `payload_base64`, decodes it through the frontend's real protocol decoder, applies it through the real store/dispatch path, then checks `expect`.

   ```json
   { "kind": "frame", "opcode": 128, "note": "keyframe",
     "payload_base64": "...", "expect": { ... } }
   ```

   `opcode` is informational (128 = 0x80 keyframe, 160 = 0xA0 overlay delta, 161 = 0xA1 viewport delta, 162 = 0xA2 rows delta).

2. **inject_offset** — state injection. Sets a nonzero local presentation offset on a window *mid-transcript*, using anchor keys that match the currently-stored frame. This is the whole point of the input suite: store-state-only transcripts were ruled insufficient, so the runner must be able to run a transcript against a frontend whose local offset is nonzero.

   ```json
   { "kind": "inject_offset", "window_id": 1, "row_offset": 3, "col_offset": 0 }
   ```

3. **pointer** — a pointer (drag) event at a content-relative row/col. The runner normalizes it through the frontend's **real** presentation offset transform (Swift `clampPresentationPoint`/`presentationScrollOffset`, Go `normalizePresentationMouse`) and checks the resulting buffer line.

   ```json
   { "kind": "pointer", "window_id": 1, "pointer_row": 2, "pointer_col": 3,
     "expect": { "normalized_buffer_line": 45 } }
   ```

### Recovery steps

The recovery family uses production transaction paths: Swift decodes the complete batch into `DecodedFrame` and calls `CommandDispatcher.dispatch`; Go decodes the same batch and enters `Model.applyCommands` through the production-frame fixture. A result is required for every `framed` step, including rejection. Applying a frame that the BEAM oracle rejects is a failure even if a later keyframe restores the same rows.

- **framed** carries `payload_base64`, a complete begin/commit transaction, `command_sizes`, and `expect`. `command_sizes` records the command boundaries observed before Manager admission; concatenating those commands must equal the bytes captured by its `port_commander`. The BEAM oracle uses these boundaries to re-decode the batch through `Frontend.Protocol.decode_recorded_frame/2`. `after_commands_base64` preserves any actual out-of-band batches emitted after that frame, including title and window background, in delivery order.
- **frame_status** records the frontend return edge: `event` is `frame_applied`, `frame_rejected`, or `window_reference_miss`, with `generation`, `frame_seq`, and the event's `last_applied_frame_seq`, numeric wire `reason`/`disposition`, or `window_id`. Both runners assert the production result emits that exact status. `ack_timeout` means the applied acknowledgement was dropped; the generator sends the outstanding lease's exact timeout identity to the real renderer without sleeping.
- **resize** carries `rows` and `cols`, the frontend-reported cell fit. The driver sends the normal resize input to a real headless Editor, takes its mailbox barrier, prepares the real submission, and runs the actual Layout pipeline on its own acknowledgement-requiring renderer. No test derives rows from pixels or line spacing (ADR-0001).
- **wheel** carries `window_id`, signed cell-unit `delta`, and `during: "commit" | "idle"`. During-commit input is delivered after the decoded transaction body has staged but before its commit. The runners use the input corpus's local-presentation seam against the committed rows, not staged rows.
- **click_after_settle** carries `window_id`, `row`, and `col`. It normalizes the settled whole-cell offset through the same production pointer transform as `pointer`; no residual animation or wall-clock delay is required.

Adversarial input frames may replace an invalid base or encode a missing/stale window overlay using the real protocol encoders. **Recovery responses are never hand-typed, reconstructed, or patched.** They are the next batch captured after `Renderer.Server.frame_status/2` or the exact lease timeout. `RecoveryDecision.decide/3` is the single pure recovery policy; `RecoveryHandler` applies its reservation, keyframe, invalidation and scheduling effects.

An altered initial delivery retains its captured `after_commands_base64`; replaying an old frame as stale input does not replay those original side channels a second time. Both clients assert the resulting title and window background even when the framed transaction is rejected. The retained-reference-miss scenario first warms and acknowledges two real panes, then rejects an unretained row reference in pane 1. Recovery keeps the generation and nonzero acknowledged base, sends full rows only for pane 1, and leaves pane 2's rows and content epoch unchanged.

#### Recovery mutation evidence

Run `scripts/check_conformance_recovery` on macOS after the ordinary `Minga` unit invocation has built and tested the same committed revision in `macos/DerivedData`. It requires the pinned BEAM/Xcode tools and fetched dependencies. Producer, consumer, and committed corpus sources must be clean. Use a new output directory for each invocation; existing evidence is never overwritten.

```bash
scripts/check_conformance_recovery
```

The collector creates a disposable worktree at committed `HEAD` with private copies of available Elixir dependencies/build artifacts. Its only source inverse changes `RecoveryDecision.keyframe/2` from `generation: lease.generation + 1` to `+ 2`. The focused no-process decision tests must fail on generation policy, and `mix conformance.gen --check` must fail on `retryable_base_sequence`'s committed-generation expectation. A build error or unrelated generator failure is not a kill.

It captures all six scenarios from the real renderer in fresh BEAM runs before and after mutation. Native replay copies only `payload_base64`, `after_commands_base64`, and `command_sizes` from the mutant into baseline transcripts. Expectations, status steps, and all other consumer input remain unchanged. Passing controls select the index without recovery (currently 37 cases), the complete candidate index (43 cases), and the named `retryable_base_sequence` case. The native mutation run selects that same named case. Only index selection changes between the paired timing controls; their frames and compiled runner are identical.

Native runs reuse the ordinary unit build through copied `.xctestrun` plans. Their test-only environment selects the replay directory, and `loadSteps` saves the exact bytes it consumed. The collector verifies those receipts against the selected files, so a cached binary reading the original corpus cannot count as a kill. The mutant must produce a named `lastCommittedGeneration` assertion failure against baseline generation two. Missing result bundles, zero tests, unrelated failures, or a failing control are inconclusive and fail the CI step.

`conformance-recovery-evidence/` contains the revision, exact source inverse, baseline and mutant producer JSON, replay data, commands/logs, `.xctestrun` plans, consumed-data receipts, `.xcresult` bundles, and `evidence.json`. The existing native CI job runs this after ordinary unit tests and uploads the directory even on failure. The collector does not rerun the full unit bundle. It verifies the exact consumed-case sets and an actual six-test increase in the paired controls, records raw result summaries and Xcode wall times, and gates the completed generic-suite time increase below 30 seconds. Both timings come from the same runner and compiled suite; historical timings are not mixed with current Xcode wall time.

Linux can collect the producer portion without making a native claim:

```bash
scripts/check_conformance_recovery --producer-only --output-dir /tmp/minga-recovery-producer-evidence
```

Removing only the handler's force-keyframe setter is a documented wire-equivalent survivor for these captures: frontend reset still emits the same keyframe bytes, while the private `force_keyframe` expectation changes. That inverse is not native kill evidence. The approved generation-policy inverse replaces it for this proof; correct reset behavior is not changed to manufacture a failure.

### Chat steps (resident agent transcript, 0x86, #2654)

The `chat/*.json` family is a distinct transcript shape for the resident agent-chat transcript stream (`gui_agent_transcript`, 0x86). Its frames are produced by the real `Minga.Frontend.Adapter.GUI.AgentTranscriptEncoder` and folded through each frontend's real store apply (Swift `AgentChatState.applyTranscript`, Go `residentTranscript.apply`), so an encoder change regenerates the corpus and drift is caught. A third leg, the BEAM oracle in `test/conformance/agent_transcript_corpus_test.exs`, re-decodes the same bytes and asserts they carry exactly what the expectations claim.

There are three chat step kinds:

1. **transcript_frame** — a single framed 0x86 message. The runner base64-decodes `payload_base64`, decodes it through the real protocol decoder, applies it through the real resident store, then asserts `expect.transcript` (the shared parity core, asserted identically on both frontends and the BEAM oracle).

   ```json
   { "kind": "transcript_frame", "opcode": 134, "note": "full_replace 8 messages",
     "payload_base64": "...",
     "expect": { "transcript": { "epoch": 1, "count": 8, "truncated": false, "message_ids": [1,2,3,4,5,6,7,8] } } }
   ```

2. **transcript_scroll** — a local scroll input (`rows`, signed: `+`down / `-`up). Go owns a top-anchored scroll offset in the store, so its runner drives the real `scrollBy` + `resolveScroll` and asserts the `go` selector. Swift's scroll is a SwiftUI `ScrollView` concern with no store effect, so its runner treats this step as a no-op (position preservation is asserted via id stability instead).

   ```json
   { "kind": "transcript_scroll", "note": "scroll up 4 rows", "rows": -4,
     "go": { "max_top": 6, "expect_top_offset": 2, "expect_pinned": false, "expect_pin_transition": "scrolled_away" } }
   ```

3. **transcript_assert** — a per-frontend position-preservation assertion. `swift` asserts the id at a store index (`ForEach(id:)` stability is what preserves the SwiftUI scroll position across an append). `go` drives `resolveScroll` at the post-frame `max_top` and asserts the reading offset is stable and the pin state is correct.

   ```json
   { "kind": "transcript_assert", "note": "reading position preserved",
     "swift": { "anchor_index": 2, "anchor_id": 3 },
     "go": { "max_top": 7, "expect_top_offset": 2, "expect_pinned": false } }
   ```

Both frontends run every chat transcript; there are no `go_skip` entries in this family. The per-frontend `swift`/`go` selectors capture the honest asymmetry between the two offset models (SwiftUI id stability vs. a store-owned top-anchored offset), while the shared `transcript_frame.expect.transcript` is what makes the resident-store parity executable. `expect_top_offset` and `expect_pin_transition` are optional (an unpinned-only or pin-only assertion omits the irrelevant key). Pin transition names are `scrolled_away`, `returned`, or absent (no edge).

### Focus steps (native keyboard ownership, 0xAA, #3512)

A picker that owns the keyboard must keep it when its window becomes key or a file drop finishes. The ten native-only focus transcripts make that promise executable instead of checking only that the owner decoded. The Swift runner creates `FocusConformanceHarness` only for entries whose category is `focus` and whose actual consumer designation is `go: false`. It uses a real offscreen `NSWindow`, real views and fields, and the production `EditorFocusPolicy`. It checks the window's actual `firstResponder`, including an `NSTextField`'s active field editor. It does not assign the expected responder itself.

Native-only focus transcripts use ordinary **frame** steps containing a real `FocusOwnerEncoder` command (`gui_focus_owner`, opcode 170), followed by **native_event** steps. Each native-only focus payload includes production-encoded `begin_frame`, a complete theme, the focus command, and `commit_frame`. The runner dispatches those decoded commands through the production transaction boundary and requires an accepted commit before checking the responder. Other corpus categories keep their existing apply path. Each generated native-only focus frame uses a fresh encoder cache, so its keyframe case emits the same owner twice rather than accidentally testing an omitted command.

```json
{
  "kind": "native_event",
  "event": "agent_overlay_visibility_changed",
  "note": "show the agent overlay",
  "args": { "visible": true },
  "expect": { "first_responder": "editor_view" }
}
```

Each event invokes the corresponding public policy method. Deferred retries settle before the runner asserts `expect.first_responder`. Unknown events fail instead of being ignored.

| Event | `args` | Policy entry point |
|-------|--------|--------------------|
| `window_did_become_key` | `{}` | `windowDidBecomeKey()` |
| `native_modal_began` | `{}` | `beginNativeModal()` |
| `native_modal_ended` | `{}` | `endNativeModalAndRestore()` |
| `native_modal_restored` | `{}` | `restoreAfterNativeModal()` |
| `swiftui_hierarchy_rebuilt` | `{}` | `swiftUIUpdateDidOccur()` |
| `file_drop_completed` | `{}` | `fileDropDidComplete()` |
| `pointer_returned` | `{}` | `pointerReturnedToEditor()` |
| `agent_overlay_visibility_changed` | `{"visible": true\|false}` | `agentOverlayVisibilityDidChange(_:)` |
| `local_text_editing_began` | `{"kind": "workspace_rename"\|"workspace_icon_search"}` | `beginLocalTextEditing(_:)` |
| `local_text_editing_ended` | Same lease `kind` as begin | `endLocalTextEditing(_:)` |
| `native_text_editing_ended` | `{}` | `nativeTextEditingDidEnd()` |
| `responder_registered` | `{"kind": "picker_query"\|"search_query"\|"inline_edit"}` | `register(_:as:)` |
| `responder_unregistered` | Same responder `kind` | `unregister` |
| `first_frame_rendered` | `{}` | `firstFrameDidRender()` |

`expect.first_responder` is one of `editor_view`, `picker_query`, `search_query`, `inline_edit`, or `local_text_field`. Both frame and native-event steps carry it. The last name means a frontend-local SwiftUI text field, not a new BEAM surface. Lease-begin events host a real field driven by the policy's published focus mirror; lease-end events end native editing, remove that host, and release the matching lease. Native-text-end events finish AppKit editing before notifying the policy.

Responders are registered at setup unless a transcript declares otherwise:

```json
"setup": { "unregistered_responders": ["inline_edit"] }
```

Only the late-registration transcript uses that metadata. It establishes `editor_view` first, then commits an inline owner whose field is missing. That frame must leave the editor focused; `responder_registered` must apply the pending inline owner without another frame. Later unregister/register steps remove an inactive field, avoiding an unrelated AppKit fallback-responder assertion.

Every native-only focus entry declares `swift: true`, `go: false`, and the exact reason `"no native responder chain; keyboard owner is BEAM-routed"`. The Go runner emits `skipped for Go: <reason>` for each named entry. Its skip-reason test requires every Go-disabled transcript, in every category, to explain the skip. The seven shared focus entries below are not skipped and never instantiate this bare native harness.

The Swift lifecycle coverage guard compares the public policy entry points with the corpus event coverage and an explicit infrastructure/query exclusion list. Adding a lifecycle method without exercising it is a test failure. Focus assertion failures identify the transcript, step index, expected responder, and actual responder on one line.

### Shared focus frames (#3518)

The seven shared `focus/` entries, selected by their actual `go: true` consumer designation, use `kind: "framed"`: `payload_base64` is the complete raw wire batch, including `begin_frame` and `commit_frame`, without the outer packet4 length. `command_sizes` records encoder-produced command boundaries for the BEAM oracle. Consumers decode the batch with their production decoder and dispatch the transaction, not the test-only unframed mutator.

Each shared step carries `expect.focus_target = {surface, responder, window_id, generation}`, derived by the existing `MingaEditor.FocusOwner.derive/1` over the scenario's editor state. The same owner is encoded by the production semantic adapter. Swift asserts the pure `FocusResolution`; Go resolves the committed focused component and checks the retained wire responder and source generation. Every shared focus transcript runs on both consumers. The additional production `ContentView`/`NSWindow` replay is macOS-specific, separate from the native-event harness above.

A shared focus step omits `transaction_result`, but both runners must observe an applied production transaction before comparing `focus_target`. An unexpected rejection cannot reuse the previous committed owner as evidence for the current step.

A framed step may set `reset_frontend: true` (otherwise false). Before decoding that step, discard the entire frontend consumer and its local presentation state. The producer's editor state is not reset. The reattach scenario marks its third step this way: the real encoder sends a keyframe while the picker remains open, but Swift and Go must recover its owner into fresh stores. The native replay destroys the previous window, GUI state, policy, and registered hierarchy, then hosts a fresh production `ContentView` before applying that same keyframe. The BEAM oracle clears its retained consumer owner before consuming the keyframe's encoded fact.

Reset also clears injected local offsets, pending wheel input, transaction results, and retained outbound status/action history. No old focus owner or local presentation state is restored into the replacement consumer.

Responder waits only observe the production hierarchy and first responder while yielding the runloop; they never call focus policy hooks, force layout, or reapply an owner to make an assertion pass. Explicit native lifecycle replay runs separately after each frame has established its own responder and AX identity. First-frame notification occurs only once per fresh consumer.

Scenarios cover picker open-close with an unchanged delta, native search open-close, file-tree rename confirm and cancel, agent toggle, a reattach keyframe while the picker owns focus, focused hover, and the empty launchpad. Rename transcripts exercise the admitted edit lifecycle; filesystem rename effects remain covered by the file-tree workflow tests. Agent input uses the editor responder and BEAM `agent` scope, not a new native field. Generations retain their source meaning: picker activation generation or file-tree edit token, and zero where there is no source generation.

Regenerate with `mix conformance.gen` after compilation and dependencies are available. Run the BEAM leg with `mix test.llm test/conformance/focus_corpus_test.exs test/minga_editor/focus_owner_test.exs`, and Go with `cd go/tui && go test ./internal/ui -run TestConformanceTranscripts`. On macOS, run `ConformanceTranscriptTests`, `FocusReplayWindowTests`, `FocusResolutionTests`, `FocusWriterGuardrailTests`, `EditorFocusPolicyTests`, `GUIObservationGuardrailTests`, and `GUIFrameSwiftUIInvalidationTests` in the existing `MingaTests` CI job. The window replay checks first responder unconditionally and AX identity when the app is active and its window is key. The signed-app Accessibility workflow remains an on-device smoke, not a prerequisite for these in-process tests.

### `expect` fields

A runner asserts only the keys present on a step; absent keys are not checked.

| Field | Meaning |
|-------|---------|
| `store_present` | Whether the resident window still exists after this frame (false = dropped, e.g. after an unresolvable ref). |
| `rows` | Ordered resident rows, each `{ "row_id": "<u64 as string>", "content_hash": <u32>, "buf_line": <u32> }`. `row_id` is a string to preserve full u64 precision through JSON. |
| `anchor` | `{ "top": <line>, "left": <col> }`, the committed viewport anchor from the current `ScrollPresentation`. |
| `cursor_row` | The window's current cursor display row. |
| `offset_discarded` | Whether applying this frame forced the frontend to discard its local offset (the real reconciliation decision). |
| `normalized_buffer_line` | (pointer steps) `anchor_top + normalized_content_row` after the offset transform. |
| `first_responder` | (focus frames and native events) Actual native responder identity, resolving an active field editor back to its owning field. |
| `focus_target` | The committed BEAM owner `{surface, responder, window_id, generation}`, checked through the frontend resolver only after the transaction applies. |
| `transaction_result` | Required for recovery `framed` steps: `{kind: "applied" | "rejected" | "window_ref_miss", generation, frame_seq}` plus numeric wire `reason`/`disposition` and `last_applied_frame_seq` for rejection, or `window_id` and `last_applied_frame_seq` for a miss. Shared focus frames omit this object but must still produce an applied transaction before their focus assertions run. |
| `last_committed` | The last successfully published `{generation, frame_seq}`; rejected frames leave both unchanged. |
| `base_frame_seq` | Decoded wire base for the delivered frame; targeted recovery retains a nonzero acknowledged base instead of becoming a global keyframe. |
| `resident_rows` | Actual committed row-store count, independent of viewport height and pixel dimensions. Recovery `rows` also carries text, asserted by both clients. |
| `pane_rects` | One `{window_id, total_rect, content_rect, text_rect, gutter_rect}` per pane, each rectangle `{row, col, width, height}` in cell units from real Layout output. |
| `content_epochs` | Retained per-window content epochs, asserted by both clients and the BEAM oracle; targeted recovery must preserve the sibling pane's epoch. |
| `window_rows` | Ordered committed rows keyed by window ID, with the same identity/hash/text checks as `rows`, so multi-pane isolation is observable. |
| `out_of_band` | Captured post-frame `title` and `window_background` observations, applied independently of transaction acceptance and asserted by both clients. |
| `keyframe` / `force_keyframe` | Wire base is zero / renderer lease intent explicitly forces a keyframe. The latter also makes omission of the handler's force-keyframe effect visible during regeneration. |

A `production_fixture` step is the compact production-size form. Its `fixture` object defines deterministic carrier sizes, row counts, edit coordinates, epochs, and generations; `operations` defines shared expected statuses and row-operation counts. It intentionally has no `payload_base64`: each client expands the same descriptor through its real resident store so repeated multi-megabyte JSON is never checked in.

## What each transcript covers

Store lifecycle (AC1):

- **production_render_boundaries** — compact descriptor expanded by BEAM, Swift, and Go into exactly 65,536 resident rows and one 65,536-byte text carrier. The shared operation transcript covers an ordinary edit, a structural insertion near row zero, retained reference and miss, stale content epoch, stale recovery generation, and reset/full recovery. The checked-in JSON stays near 1 KiB; clients deterministically expand it in memory and assert the same statuses and semantic row-operation counts.
- **keyframe_decode** — 0x80 keyframe decodes to a resident row set keyed by `row_id + content_hash`, with the committed anchor.
- **rows_delta_ref_resolution** — 0xA2 resolves retained refs by `row_id + content_hash` alongside one full row.
- **ref_miss_full_recovery** — a 0xA2 ref to an unretained row drops the window; the next 0x80 recovery frame rebuilds it.
- **cursor_only_overlay_delta** — 0xA0 moves the cursor without touching rows or the anchor.
- **layout_generation_full_replace** — a `layout_generation` change mismatches the anchor key, discarding the offset and replacing rows.
- **reset_required_discard** — a `reset_required` (full_refresh) frame discards the local offset.

Input resolution seams (AC2):

- **drag_selection_active_offset** — a drag pointer under a nonzero local offset normalizes to the visually-correct buffer line.
- **hml_after_scroll_report** — an H/M/L echo commit (same anchor, same `scroll_seq`) moves only the cursor and keeps the offset (no re-anchor storm).
- **scroll_seq_strictly_newer_discard** — a strictly-newer `scroll_seq` with an identical anchor key forces a discard.
- **same_top_jump_discards** — an authoritative jump (zz already centered, a search hit already on screen) lands on the previous top but still bumps `scroll_seq` via the explicit authoritative-scroll marker, so the frontend discards its local offset (#2652).
- **wheel_momentum_during_ctrl_d** — momentum keeps feeding local offset while ctrl-d's authoritative anchors land on the same top; each `scroll_seq` bump discards the leftover offset.

Resident agent transcript (0x86, #2654):

- **append_while_scrolled_up** — a bottom append while the reader is scrolled up preserves the reading position: Swift's anchor id stays at its store index, Go's top-anchored offset is unchanged by the growth.
- **pin_to_bottom_resume** — scroll up (unpin, emit the scrolled-away edge), scroll back to the bottom (re-pin, emit the returned edge), then a following append is followed (Go stays pinned; the Swift store's newest message is at the tail the view follows).
- **session_switch_full_replace** — a full_replace at a new epoch resets the resident store to the new session and re-pins to the bottom, discarding the prior local offset.
- **trim_front_eviction_midstream** — streaming past the resident byte cap evicts the oldest messages from the store front (append `trim_front`) and flags the stream `truncated`, instead of degrading to a full_replace per frame.
- **epoch_flip_midstream** — an in-epoch append followed by an epoch flip; the append stays incremental, the epoch flip forces a full_replace even with unchanged messages.
- **streaming_tail_patch** — the streaming last message is patched in place by id (same id, new content); the store stays count 2 with ids [1, 2], catching a frontend that appends instead of upserting.

## Metal pixel composition (`pixels/*.json`, #3520)

Pixel transcripts use the recovery family's production `framed` step: its `payload_base64` is the actual Manager batch with only the packet-4 transport prefix removed, not hand-authored begin/commit bytes.
Theme, gutter and pane geometry are committed before the production `CoreTextMetalRenderer` renders the dispatcher's `committedEditorSnapshot` into an offscreen drawable.

```json
{
  "kind": "framed",
  "swift_only": true,
  "payload_base64": "...",
  "expect": {
    "transaction_result": {"kind": "applied", "generation": 1, "frame_seq": 1},
    "pixels": [
      {"region": "frame edge", "cells": [5, 35, 1, 1],
       "assert": "color", "color": "0x202020", "tolerance": 0.02},
      {"region": "spaced glyph row", "cells": [2, 8, 1, 12],
       "assert": "occupied", "color": "0x202020"},
      {"region": "old glyph row", "cells": [4, 8, 1, 12],
       "assert": "empty", "color": "0x202020"}
    ]
  }
}
```

`cells` is `[row, col, rows, cols]`, absolute to the **editor surface**, with top-left origin (not relative to the text or gutter).
Regions are derived from the encoded window's geometry and carried rows.
Fractional cell coordinates are permitted; there are no pixel-unit regions.
Swift converts using the fixture font **Menlo 13, scale 1**: X uses `cellWidth`; Y uses `cellHeight × committed lineSpacing`.
Bounds round outward and must fit the drawable.
Font spacing is never emulated in the model expectations.

`color` requires every sampled pixel to match `0xRRGGBB`.
`occupied` requires at least one pixel differing from the reference/background; `empty` requires none.
`color` defaults to the neutral fixture background `0x202020` when omitted.
The default tolerance is **0.02 squared Euclidean RGB distance** in normalized, sRGB-encoded readback channels, not an allowed fraction of wrong pixels.
Saturated red `0xE01010` and blue `0x1010E0` distinguish fixture glyphs.
Failures identify transcript, step, named region, cell rectangle, measured matching/occupancy count and the sampled centre pixel's RGBA channels.

`swift_only: true` declares **only pixel evidence** Swift-specific.
`frontends.go` remains true: Go still dispatches the same framed bytes and asserts all model expectations, ignoring only `expect.pixels`.
Pixels are evidence for composition, **never a substitute for, or gate on, model state**.
There are no golden images, SwiftUI shell captures, Accessibility trust grants, or displayed windows in the pixel suite.

The nested `ConformanceTranscriptTests.Pixels` suite is serialized.
Each transcript acquires one Metal device, shared by its production renderer and readback queue, and reuses the renderer across its steps.
An unavailable device disables the pixel suite locally with a reason; `MINGA_REQUIRE_METAL=1` makes it run and fail instead (required by the existing macOS CI job).
A rejected or uncommitted frame fails with **"no committed snapshot"**; it never renders the previous good snapshot.

### Timing and honest mutation evidence

The existing Swift CI job runs:

```bash
mix protocol.gen
mix conformance.gen
cd macos && xcodegen generate
cd ..
MINGA_REQUIRE_METAL=1 python3 scripts/check_conformance_pixels --mutations
```

The script delegates the complete unit run to `scripts/test_macos_unit`, so both active-window focus suites execute in separate processes and remain part of the unit evidence.
It then warms the focused conformance suite and measures it without/with the pixel sub-suite using the same Debug build products.
`conformance-pixel-evidence/evidence.json` records revision, device information, macOS build, commands, exit codes, wall-clock durations, the added-pixel delta and the historical whole-unit baseline (2026-10-29: **136 s / 1555 tests**).
The pixel increment budget is **10 s**.
CI uploads JSON, logs and result bundles; copy measured values into the PR rather than presenting historical numbers as new measurements.

The three scenarios name the actual historical fixes: background fill `6ab625b2c` (#2687), spaced IME/accessibility geometry `966352a7c` (#2674), and captured-snapshot local scroll reconciliation `559792551` (#3397).
**A direct Metal region cannot prove an IME or view-owned scroll fix.**
The additional production `ContentViewTests.conformanceSpacedInputGeometry` and `conformanceScrollPublicationUsesCapturedCommit` regressions cover those owners.
The spacing test uses an unshown window only for the real screen-point conversion; the offscreen Metal transcripts themselves do not need a window.

Because intervening refactors moved the original changes, the script applies explicit **production-equivalent inverses**, not a claimed successful `git revert`, in isolated disposable worktrees.
Each mutant uses a private Elixir build cache rather than sharing the candidate checkout's mutable build path.
Spacing rolls current IME row geometry back to unspaced height; scroll reconciliation consumes the old visible snapshot instead of the captured commit.
A mutation kill requires a passing control and the **named behavioral test** failing in an xcresult.
Compilation failures, zero tests, missing results and unrelated failures are inconclusive and fail the evidence command.

Background fill is intentionally treated differently: the current explicit quad and production Metal clear both derive from `defaultBg`.
Removing only the fill is expected to **survive**, demonstrating that the historical composition operation is redundant for these current pixels, not a mutation kill.
The background transcript still asserts that the frame edge is painted.
Never change the clear color, fake a snapshot, or claim this surviving historical mutation was killed just to make the evidence look stronger.
