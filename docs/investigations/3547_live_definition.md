# R0 #3547: bounded stable-name replacement works in the fixture

The pinned runtime passed the consecutive v1 → v2 → rejected candidate → restored v2 → v3 sequence in one BEAM. Both entry points returned helper-dependent values from the accepted revision. One instance failed its v2 upgrade, retained its exact original inert data, and recovered under v3 without a historical executable version. All four admission-owner interruption schedules remained explicitly unavailable. This supports specifying a restricted live-definition family, not shipping a production loader.

## Reproduce

Copy the self-contained fixture out of the checkout before running it. Prerequisites are the asdf installations for Elixir `1.20.5-otp-29` and Erlang `29.1.2`; no Mix, dependencies, application configuration or build caches are used. From the repository root:

```sh
experiment="$(mktemp -d /tmp/minga-r0-3547-XXXXXXXX)"
cp -R scripts/investigations/3547_live_definition/. "$experiment/"
PATH="$HOME/.asdf/installs/erlang/29.1.2/bin:$PATH" ELIXIR_ERL_OPTIONS='+S 2:2' "$HOME/.asdf/installs/elixir/1.20.5-otp-29/bin/elixir" "$experiment/run.exs"
```

The driver freezes its inputs, starts four disposable compilation OS VMs, then five fresh execution OS VMs. The complete consecutive update sequence runs in the `coherent` VM. Each owner-death schedule runs in its own VM so a deliberately unavailable source does not need an invented recovery operation to start the next schedule. Definition compilation never runs in an executing fixture VM. Execution VMs assert all three definition modules were initially unloaded, then install only prepared binaries with OTP `prepare_loading/1` and `finish_loading/1`. Non-destructive `soft_purge/1` must return true; no force purge or code deletion is used.

Authoritative public receipts: `docs/investigations/3547_live_definition/evidence/run-1794442801013505/`. Every `prepare-*.status` and `fixture-*.status` is `0`; the driver completed with `ALL_SCHEDULES_PASS`. Each operation has a `.command`, `.log` and `.status`. `inputs/` contains copies of the exact scripts, product contract and source snapshots frozen read-only during execution. `SHA256SUMS` identifies all inputs; preparation logs identify each binary SHA-256. The local run also retains its 12 prepared BEAM binaries in `artifacts/`; generated binary files are intentionally not tracked. Loaded-module fingerprints use the BEAM code MD5 compared with the admitted binary's `beam_lib.md5/1`, not a claim that MD5 is a security digest. Reproduction emits a new evidence directory beside the disposable copy.

The final executable scripts were formatted with the pinned runtime's `Code.format_string!/1` before freezing; `format.command`, `format.log` and `format.status` retain the command and its successful empty output. This experiment ran no application build, lint or broad suite and made no commit, PR, production-file edit or user-configuration change. Any later integration gates are separate from this runtime evidence, which is neither production verification nor an operation benchmark.

## Implementation map

| File / symbol | Responsibility |
|---|---|
| `run.exs` | Freeze inputs; launch independent preparation and execution VMs; retain raw commands, output and exit statuses. Resolve asdf tools from the current user's home, without account-specific source paths. |
| `prepare.exs` | Compile one frozen source snapshot in a disposable VM, check the exact three-module inventory, emit read-only binaries and hashes, exit. This is not the production hostile-artifact validation path. |
| `snapshots/{v1,v2,rejected,v3}.exs` | Exactly two stable entry modules, `R0Definition.Left` and `R0Definition.Right`, and one owned shared helper, `R0Definition.Helper`. Revisions change constants/upgrade behavior, never module names. |
| `fixture.exs`, `R0.Owner` | Real GenServer admission, active callback tracking, drain bound, explicit source/module ownership, revision/epoch/request correlation, per-instance inert data and usability. Installation and publication remain closed until their prerequisites settle. |
| `fixture.exs`, `R0.Installer` | One separately monitored, host-owned installer per attempt. Record VM-local provenance in an independent Agent; batch-install, validate and restore; pause at exact death boundaries. |
| `fixture.exs`, `R0.Gate` / `R0.Schedule` | Host-owned pre-helper barriers and fixed schedules. Workers are created by the host and tracked until process `DOWN`. Source code creates no workers, tasks, escaped closures or callbacks. |
| `PRODUCT_CONTRACT.txt` | The established Save/grant contract, reproduced verbatim below. |

The two instance models are `modern` (`n: 7`) and `legacy` (`n: 11`), with inert schema/data, last-attempted revision and usability. The definition never owns a per-instance executable version. Both entries operate through the same current shared helper. At v1 their modern-instance results are `120` / `1020`; at v2 `230` / `2030`; at v3 `340` / `3040`. Recovered legacy results are `344` / `3044`.

## Established product choices, demonstrated restrictions, unproved enforcement

The Save/grant contract below is established product policy, reproduced verbatim. It was not implemented or verified by the loader fixture:

> An ordinary Save attempts one immutable source-unit snapshot, not an extra Apply command. Grouped saves specify membership and begin/complete/abort ownership; completion attempts exactly one snapshot. Interrupted groups stay visibly pending or aborted, never inferred complete by elapsed time. Source-save and activation outcomes are separate. A revocable session grant covers source execution during preparation, including compilation, as well as installation; authority is checked before preparation and before installation/publication without prompting for each revision within scope. Revocation closes new admission without undoing prior effects. Pin this written contract before B0/L0 implementation; R0 does not implement its filesystem/UI path.

The executed source family has no `@on_load`, runtime module creation, escaped callbacks/processes, dependency replacement or external effects from definition validation. Definitions compute over inert maps/numbers and call a known host-owned barrier. The harness owns worker creation, completion, installer serialization and result publication. These are inspected and exercised properties of these four snapshots, not a tested method of confining arbitrary source. No sandbox is claimed. Trusted compilation and execution retain OS-user privileges.

Production must still define and enforce eligible declarations, supported callback behavior, source/module ownership, preparation authority, publication authority and revocation across the real call paths. Grouped saves need explicit begin/complete/abort ownership and immutable membership; no elapsed-time inference. R0 does not weaken ADR-0003 for arbitrary extensions or dependencies. Its restricted-API exit clause allows the next separate design decision, not an automatic exemption.

The current production references remain unchanged: ADR-0003 requires a fresh VM for arbitrary extension code updates; `ArtifactAdmission` protects full module ownership and fails an interrupted loading generation; `ArtifactGenerationState` retains sanitized provenance without old caller/attempt authority across owner restart; `EXTENSION_API.md` describes private immutable snapshots, independent preparation/validation and full trust rather than a sandbox. The prototype is evidence beside those contracts, not a replacement implementation.

## Recommendation and next smallest child

Specify and review the restricted source family and fail-closed admission contract before B0/L0 implementation. Its concrete deliverable should settle the allowed declaration/callback set, complete module inventory and collision rules, bounded callback/drain behavior, VM-local artifact retention and installer lifetime, rejected-candidate restoration, and the unavailable outcome after interrupted authority. Carry independent inert-instance upgrade into S0; do not require dormant records to participate in activation.

Keep production automatic recovery blocked unless a follow-on investigation or the real owner proves a specific reconciliation protocol. Separately qualify packaged preparation and exercise the written Save/grant contract, including revocation during compilation, interruption of grouped saves, and rejected activation with saved source still inspectable. S0/L0 must settle per-record committed/conflict/definite-failure/uncertain outcomes, cross-process writer fencing and settlement while an instance is unavailable before durable implementation.

This investigation neither needs nor authorizes a second long-lived authoring VM, a full core rewrite, a smaller programmable release, release publication or distribution-repository edits.
