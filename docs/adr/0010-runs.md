# ADR-0010: Commands you do not type into are runs, with one record, one runner and one buffer

**Status:** Proposed (2026-11-27). Design: [runs.md](../design/runs.md). Plan: the [runs workstream](https://github.com/jsmestad/minga/blob/main/docs/workstreams/runs.md). Amends [ADR-0008](0008-terminal-engine.md) when slice S5 lands. Depends on spike A in the workstream.

## Decision

1. **A run is a command with a known command line and no keyboard input.** `:!cmd`, the test commands, the project command and every command Minga's agent runs are runs. An interactive shell is a terminal (ADR-0008), not a run.
2. **One record.** `Minga.Run` is a pure value in Layer 0: a struct with tagged states (`:needs_you`, `{:working, started_at}`, `{:done, ended_at}`, `{:failed, reason}`, `{:stopped, by}`), a separate `superseded_by` field, and transitions that pattern-match their valid source states.
3. **One owner per project.** A Layer 1 service owns runs: one `Minga.Run.Log` per project root is the only writer of records and of the `*run*` buffer. One `Minga.Run.Worker` per run owns the process, line assembly, matching, caps and timers, and reports to the Log. One event, `:run_changed`, replaces `:command_done`.
4. **One runner.** The editor's commands and the agent's shell tool share one runner, built from the agent's existing process-group and bounded-output code. `Minga.CommandOutput` is deleted. Both `MingaEditor` and `MingaAgent` call `Minga.Run`; `Minga.Run` never references the agent. An approval's decision stays with the agent.
5. **One PTY helper.** A native helper, `minga-run`, gives the command a PTY for stdout and stderr and `/dev/null` for stdin, owns the process group, and stops it with signal escalation. It reports a command that opened the controlling terminal for input.
6. **One buffer per project.** `*run*` is buffer text through the resident-row path. Block ranges are a value inside the buffer state (`Minga.Buffer.Blocks`), written in the same call as the text, so text and block structure never disagree in a frame.
7. **Backpressure at the worker.** A worker asks for the next chunk only after its last append returns and flushes at most about 30 times a second. The modeline's update rate is bounded by publishing `:run_changed` only when a quantized summary changes.

## Context

Today `Minga.CommandOutput` runs one command per name through an Erlang Port with a pipe. It appends each chunk with a synchronous buffer call, stops a command with `Port.close` (which leaves the process group running), and has no flow control. The agent's shell tool has the right process handling and a credit-based output reader, but it is private to the agent. So the editor and the agent run commands two different ways, and only one of them can be stopped.

The design for runs needs more than either gives: coloured, line-buffered output, a visible state per run, a stop that ends the process group, errors parsed once on the BEAM, and Minga's commands shown beside yours.

## Options compared

**Keep the pipe.** Most programs block-buffer on a pipe and drop colour, so output arrives late and in bursts, and "the command asked for keyboard input" cannot be seen. It cannot meet the design.

**Wrap commands in `script` or `unbuffer`.** Flags differ by platform, `unbuffer` needs Tcl, and the PTY session escapes the group kill.

**A PTY helper with input on `/dev/null`.** Programs see a terminal for output and none for input. They colour and line-buffer their output, and they skip interactive modes that would hang. It costs a new native helper and release artifact, and tests that spawn it must be serialized.

**One buffer per run.** Simple ranges, no interleaving. It needs a second surface to switch between runs and hides Minga's commands from the place you look at your own.

## Why this one

One record and one runner mean a command behaves the same whether you or Minga started it, and stopping works everywhere. The PTY helper with no input gives real output without the detection work a full terminal needs; its code is the base for `minga-terminal` later. One buffer keeps the block grammar the terminal design already defines, and committing block ranges with the text removes a class of frames where the two disagree.

## Checks that could reverse this

- Spike A: if a command that opens the terminal for input cannot be detected, the "needs keyboard input" reason is dropped and those commands end with their own exit code.
- Spike B: if row deltas cannot keep up with two runs streaming into one folded buffer, the buffer becomes one per run and the design returns to review.

## Consequences

- Folded buffers must be resident before `*run*` ships (slice S0).
- The agent's model reads PTY output with colour stripped. Programs that detect a terminal print differently from today's pipe, so the agent's transcripts change and must be compared in S5.
- Runs set a documented environment: pagers to `cat`, plain progress for known build tools, on top of the login shell's environment.
- `:command_done` subscribers move to `:run_changed`.
- The terminal (ADR-0008) reuses the helper's PTY and process-group code and the block value. `*minga-shell*` as a separate buffer would be withdrawn at slice S5. Until this ADR is accepted, `docs/design/terminal.md` and issue #4061 govern it.
